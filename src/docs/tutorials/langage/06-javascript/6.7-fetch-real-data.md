## Terms used in this lesson

- **HTTP request** — a real message a program sends asking a server for
  a specific resource, and the real response the server sends back. This
  whole curriculum's own Phase 9 (SQL) and Phase 10 (Android) both
  eventually build a real server to answer one; this lesson's own real
  request, for now, asks a much simpler real target: one static file,
  `data.json`, sitting right next to `app.js` on this same machine.
- **JSON (JavaScript Object Notation)** — a real, plain-text data format,
  intentionally close to JavaScript's own object and array literal
  syntax (Lesson 6.2), but stricter and language-independent: every
  real key must be a quoted string, no trailing comma is ever allowed,
  and no comment syntax exists at all. It exists so structured data —
  not code — can be written, sent over a network, and read back by
  *any* language, not only JavaScript.
- **Same-origin restriction on `file://`** — a real browser security
  rule, proven directly this session: a page opened as a local file
  (`file:///...`) is forbidden from making a real `fetch` request at
  all, even to another file sitting in the identical folder. It exists
  because a `file://` page has no real, meaningful "origin" a browser
  can compare against, the same real check that (for pages loaded over
  real `http://` or `https://`) normally decides whether one site is
  allowed to request another's data.
- **Promise** (briefly — full, real treatment in Lesson 6.8) — a real
  JavaScript object representing a value that isn't available yet, but
  will be, eventually. `fetch`'s own real return value, below, is one.
  This lesson uses one without yet explaining its own real internal
  states or `async`/`await`, JavaScript's own newer syntax for working
  with one — both are this whole phase's own next lesson's real
  subject.

## Objects and methods used

- **`fetch(url)`**
  *What it is:* a real, global function that starts a real HTTP request
  for the given URL.
  *Implementation:* per MDN's own documentation, fetched and quoted this
  session, the function "starts the process of fetching a resource from
  the network, returning a promise that is fulfilled once the response
  is available," and "the promise resolves to the `Response` object
  representing the response to your request."
  *Its use:* this lesson's own real code calls it with the literal
  string `"data.json"`, requesting that file relative to `index.html`'s
  own real location.
  - *Type:* a global function, not a method on any object this project
    has already found.
  - *Responsibility:* start a real, asynchronous HTTP request and hand
    back a real placeholder — a Promise — for the eventual response,
    without blocking any other code in the file from continuing to run
    in the meantime.
  - *Depends on:* a real URL, here a plain relative path resolved
    against the page's own real location.
  - *Connects to:* called directly here, at the bottom of `app.js`; its
    own real return value is what `.then()`, immediately below, is
    called on.
  - *Shape:* the real, first real network boundary this whole project
    has ever crossed — everything before this call is pure, local
    JavaScript; everything after it depends on a real request actually
    succeeding.

- **`Response.json()`**
  *What it is:* a real method that reads a real HTTP response's own
  body and parses it as JSON.
  *Implementation:* per MDN's own documentation, fetched and quoted this
  session, the method "takes a `Response` stream and reads it to
  completion," returning "a Promise that resolves to a JavaScript
  object. This object could be anything that can be represented by
  JSON — an object, an array, a string, a number…"
  *Its use:* this lesson's own real code calls it on the `Response`
  object `fetch`'s own Promise resolves to, turning `data.json`'s own
  real text into a real, usable JavaScript array.
  - *Type:* an instance method, defined on `Response`.
  - *Responsibility:* read a real response body, in full, and parse it
    according to JSON's own real grammar, producing whatever real
    JavaScript value that text represents.
  - *Depends on:* being called on a real `Response` object, and that
    response's own real body actually being valid JSON text.
  - *Connects to:* called on the object `fetch`'s own first `.then`
    callback receives; its own real return value — another Promise — is
    what this lesson's own second `.then` callback finally receives as
    real, usable data.
  - *Shape:* the real boundary between "raw bytes a server sent" and
    "an actual JavaScript value this project's own code can read `.id`,
    `.title`, `.category`, and `.duration` off of," the identical real
    shape Lesson 6.2 already established for `entries`.

- **`Promise.prototype.then(onFulfilled)`**
  *What it is:* a real method, called on a Promise, that registers a
  callback to run once that Promise's own real, eventual value is
  ready.
  *Implementation:* per MDN's own documentation, fetched and quoted this
  session, the method "takes up to two arguments: callback functions for
  the fulfilled and rejected cases of the `Promise`," and itself
  "immediately returns another `Promise` object, allowing you to chain
  calls to other promise methods."
  *Its use:* this lesson's own real code calls it twice in a row,
  chained — once on the Promise `fetch` returns, and again on the
  Promise `.json()` returns — each callback receiving whatever real
  value the previous step's own Promise ultimately resolved to.
  - *Type:* an instance method, defined on `Promise`.
  - *Responsibility:* run the given callback exactly once, only once its
    own Promise's real value is actually ready, and produce a new,
    real, chainable Promise of its own around whatever that callback
    itself returns.
  - *Depends on:* being called on a real Promise, plus a real callback
    function to run.
  - *Connects to:* called first on `fetch("data.json")`'s own real
    return value; its own real return value is itself a Promise,
    letting a second `.then` be chained directly after it, forming a
    real, ordered pipeline.
  - *Shape:* the real, current mechanism this lesson uses to work with
    an eventual value — Lesson 6.8, immediately next, introduces
    `async`/`await` as a real, different, often clearer syntax for the
    identical real underlying mechanism.
