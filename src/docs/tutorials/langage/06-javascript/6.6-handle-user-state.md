**What you will build:** `code/05-html-css/Data/app.js` gains real,
top-level mutable state — `let selectedArticle = null;` — read and
reassigned by every generated `<article>`'s own click handler, plus a

nothing yet remembers, across *separate* clicks on *different* records,
which one is currently selected — and Lesson 5.5's own real detail view
still shows whichever record Lesson 5.2 happened to hand-write into it,
no matter what a reader actually clicks.

**What you need to know first:** Lesson 6.5's own real closures, each

## Terms used in this lesson

- **Mutable state** — a real value, held in a variable, that is
  expected to change over the real lifetime of a running program, as
  opposed to a value fixed once and never reassigned. `selectedArticle`,
  this lesson's own new variable, is real mutable state: `null` at
  first, then reassigned to a genuinely different real element every
  time a different record is clicked.
- **`let`** — a real JavaScript keyword, declaring a binding whose own
  assigned value *can* be reassigned later — unlike `const`, this whole
  project's own only binding keyword until this lesson, which forbids
  it. It exists specifically for values this lesson's own Terms entry
  above already named: ones a program genuinely needs to change over
  time.
- **Shared closure variable** — a real, single variable, declared once,
  that more than one separate closure independently reads and mutates —
  a real, deliberate contrast with Lesson 6.5's own `entry`, where every
  closure instead got its *own*, separate, independent captured value.

## Objects and methods used

- **`Element.querySelector(selector)`**
  *What it is:* a real method that searches inside one specific
  element for the first descendant matching a given CSS selector.
  *Implementation:* per MDN's own documentation, fetched and quoted
  this session, the method "returns the first element that is a
  descendant of the element on which it is invoked that matches the
  specified group of selectors," and, per that same documentation, "if
  no matches are found, the returned value is `null`."
  *Its use:* this lesson's own real code calls it on `entryDetail`,
  searching specifically inside `#entry-detail` (never the whole
  document) for whatever `<article>` currently sits there, so it can be
  replaced.
  - *Type:* an instance method, defined on `Element`.
  - *Responsibility:* search only within the element it's called on, in
    real document order, and return the first real match for the given
    selector, or honestly report none exists by returning `null`.
  - *Depends on:* being called on a real element, plus a real CSS
    selector string.
  - *Connects to:* called here on `entryDetail`, the constant this
    lesson's own first real line finds via `getElementById`; its own
    real return value is what `.replaceWith()`, immediately below, is
    called on.
  - *Shape:* a real, scoped search — unlike Lesson 6.1's own
    `document.getElementById`, which always searches the *entire*
    document, `querySelector`, called on a specific element, only ever
    looks inside that one element's own real subtree.

- **`Element.replaceWith(...nodesOrStrings)`**
  *What it is:* a real method that swaps the element it's called on,
  in place, for one or more given nodes or strings.
  *Implementation:* per MDN's own documentation, fetched and quoted this
  session, the method "replaces this `Element` in the children list of
  its parent with a set of `Node` objects or strings."
  *Its use:* this lesson's own real code calls it on whatever `<article>`
  `querySelector` just found inside `#entry-detail`, replacing it
  directly with a freshly-built one from `createEntryElement`.
  - *Type:* an instance method, defined on `Element`.
  - *Responsibility:* remove the element it's called on from its
    parent's own list of children, and insert the given replacement(s)
    in that exact same real position.
  - *Depends on:* being called on a real element that currently has a
    real parent, plus at least one real node or string to replace it
    with.
  - *Connects to:* called here on the element `querySelector` just
    found; its own real argument is whatever `createEntryElement`
    returns for the newly-selected record.
  - *Shape:* the real, final step of this lesson's own detail-rendering
    pipeline — the one call that actually makes a new selection visible
    inside `#entry-detail`.

- **`DOMTokenList.remove(token)`** (a sibling of Lesson 6.1's own
  `.toggle` and Lesson 6.3's own `.add`)
  *What it is:* a real method that removes a given class name from an
  element's own `class` attribute, if present.
  *Implementation:* per MDN's own documentation, fetched and quoted this
  session, the method "removes the specified tokens from the list."
  *Its use:* this lesson's own real code calls it on whichever article
  was *previously* selected, immediately before marking a new one,
  ensuring only one real `<article>` ever carries `class="selected"` at
  once.
  - *Type:* an instance method, defined on `DOMTokenList`.
  - *Responsibility:* ensure a given class name is absent from the
    list, doing nothing if it already was.
  - *Depends on:* being called on a real `DOMTokenList`, plus one real
    string naming the class to remove.
  - *Connects to:* called on `selectedArticle.classList` — the
    previously-selected element, read from this lesson's own new shared
    variable, not from any fresh DOM lookup.
  - *Shape:* the real, exact inverse of Lesson 6.3's own `.add`,
    completing the same real family of three real DOMTokenList mutators
    this project now uses: `.toggle` (Lesson 6.1), `.add` (Lesson 6.3),
