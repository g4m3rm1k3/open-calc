## Terms used in this lesson

- **`<script>` element** — a real HTML element whose job is to load and
  run JavaScript inside the page. It exists because HTML and CSS, on
  their own, can only describe structure and appearance — neither one
  can respond to anything a reader does. Without a `<script>` element
  somewhere in the document, no JavaScript in this project would ever
  run at all, no matter how correct the file it lives in might be.
- **The DOM (Document Object Model)** — the browser's own live, in-memory
  tree of every element on the page, built once from the parsed HTML and
  then kept in sync with anything JavaScript does to it afterward. It
  exists as a genuinely separate thing from the HTML source file itself:
  editing `index.html` on disk does nothing to a page already open in a
  browser, but changing the DOM — the tree the browser is actually
  rendering from, right now — changes what a reader sees immediately.
  Every object and method in this lesson's own Objects and methods
  section below is a way of reading or changing some piece of this tree.
- **Event** — a real notification the browser generates the instant
  something happens that a page might care about: a click, a key press,
  a network response arriving. An event, by itself, does nothing —
  nothing observes it unless something is specifically listening.
- **Event listener** — a function registered, ahead of time, to run
  automatically whenever a specific kind of event happens on a specific
  target. It exists so a page's own code doesn't have to sit in a loop
  constantly asking "has anything happened yet?" — the browser does that
  watching, and calls back into a page's own code only when there's
  actually something to report.
- **Arrow function** — a function written as `(parameters) => { body }`
  instead of the `function` keyword. This lesson's own event handler,
  below, is one. Beyond the shorter syntax, an arrow function's most
  consequential real difference from an ordinary `function` — what it
  does with the keyword `this` — doesn't actually matter to anything
  this lesson builds; Lesson 6.11, later in this same phase, is where
  that difference becomes the whole real subject, once this project
  finally writes code where it matters.

## Objects and methods used

- **`document`**
  *What it is:* the single, real global object every piece of
  JavaScript running in a browser tab already has access to, representing
  the whole loaded page.
  *Implementation:* an instance of the `Document` interface — a real,
  live object, not a class the reader ever constructs themselves; the
  browser creates exactly one of these per page and hands it to every
  script that runs.
  *Its use:* this lesson's own real code reads `document` first,
  immediately, because every other DOM object this whole curriculum will
  ever touch — every element, every attribute — is reached by starting
  from it.
  - *Type:* a global object, already constructed by the browser before
    any script on the page runs.
  - *Responsibility:* represents the entire loaded page as one live
    object, and serves as the real, single starting point for finding,
    creating, or removing any element in the DOM.
  - *Depends on:* nothing a script provides — it exists the moment the
    browser begins parsing the HTML document, before this lesson's own
    `<script>` tag is even reached.
  - *Connects to:* every DOM method this whole curriculum will call is
    reached either directly on `document` (as this lesson's own
    `getElementById` is) or on some element `document` was used to find
    first.
  - *Shape:* the real root of the entire DOM — a global, ambient
    resource, not something any script imports or creates.

- **`document.getElementById(id)`**
  *What it is:* a real method that searches the whole document for one
  specific element by its `id` attribute.
  *Implementation:* per MDN's own documentation, fetched and quoted this
  session, the method "returns an `Element` object representing the
  element whose `id` property matches the specified string," and its
  real return value is "an `Element` object describing the DOM element
  object matching the specified ID, or `null` if no matching element was
  found in the document." Its one real parameter, `id`, is documented as
  "a case-sensitive string which is unique within the document."
  *Its use:* this lesson's own real code calls it with the exact string
  `"entry-list"` — Lesson 5.8's own real `id` value — to get a real,
  live reference to that one specific `<section>`, not a copy or a
  description of it.
  - *Type:* an instance method, called on `document`.
  - *Responsibility:* find and return the one element in the whole
    document whose `id` attribute exactly matches the given string, or
    honestly report that none exists by returning `null` — never
    throwing, never returning more than one.
  - *Depends on:* a single string argument, and, per Lesson 5.8's own
    real `id` uniqueness guarantee (MDN's own specification, already
    quoted there), a document where at most one element actually carries
    that `id`.
  - *Connects to:* called on `document`; its real return value, here
    stored in the constant `entryList`, becomes the object every later
    line in this lesson calls a method on.
  - *Shape:* the real, first rung of the DOM — the most direct way a
    script reaches from "the whole page" to "one specific, already-named
    element," which is exactly why Lesson 5.8 built the `id` this method
    depends on before this phase ever needed it.

- **`EventTarget.addEventListener(type, listener)`**
  *What it is:* a real method that registers a function to run whenever
  a specific kind of event happens on the object it's called on.
  *Implementation:* per MDN's own documentation, fetched and quoted this
  session, the method "sets up a function that will be called whenever
  the specified event is delivered to the target." Its `type` parameter
  is "a case-sensitive string representing the event type to listen
  for"; its `listener` parameter is "the object that receives a
  notification... when an event of the specified type occurs. This
  must be `null`, an object with a `handleEvent()` method, or a
  JavaScript function."
  *Its use:* this lesson's own real code calls it on `entryList` with
  `"click"` and an arrow function, registering that function to run every
  time a reader clicks anywhere inside that section.
  - *Type:* an instance method, defined on the `EventTarget` interface —
    not `Element` itself, but an interface `Element` (through `Node`)
    implements, which is the real reason `addEventListener` works
    identically on an element, on `document`, and on the whole browser
    `window`.
  - *Responsibility:* watch the object it was called on for events of
    exactly the named type, and call the given function, in order, every
    single time one occurs, for as long as the listener stays registered.
  - *Depends on:* being called on some real object that implements
    `EventTarget` (`entryList` here), a real event-type string, and a
    real function to call back.
  - *Connects to:* called on `entryList`, the exact object
    `getElementById` returned above; the browser itself is what actually
    invokes the `listener` function later, not any line in this project's
    own code — this lesson's own code only ever registers it.
  - *Shape:* the real boundary between this project's own code and the
    browser's own event system — everything on one side of this call is
    ordinary, synchronous JavaScript; everything on the other side runs
    later, asynchronously, whenever a reader actually clicks.

- **`Element.classList`**
  *What it is:* a real, read-only property giving script access to an
  element's own `class` attribute as a structured collection, not a
  single string to parse by hand.
  *Implementation:* per MDN's own documentation, fetched and quoted this
  session, the property "contains a live `DOMTokenList` collection
  representing the `class` attribute of the element" — "live" meaning
  this real object stays in sync with the element's actual `class`
  attribute from one read to the next, never a frozen snapshot.
  *Its use:* this lesson's own real code reads `entryList.classList`
  immediately before calling `.toggle()` on it, reaching the one real
  object that method actually lives on.
  - *Type:* a read-only instance property, defined on `Element`.
  - *Responsibility:* expose the element's own `class` attribute as a
    real, structured `DOMTokenList` — add, remove, and check individual
    class names without a script ever having to split or rebuild the
    attribute's raw string value by hand.
  - *Depends on:* being read on a real `Element` — here, `entryList`.
  - *Connects to:* reads from `entryList`'s own `class` attribute
    (currently absent, since Lesson 5.8 gave this section an `id` but no
    `class`); its own real return value is what `.toggle()`, immediately
    below, is called on.
  - *Shape:* a real, structured view onto one specific HTML attribute —
    the same real relationship Lesson 5.8's own `dataset` Terms entry
    already described for `data-*` attributes, applied here to `class`
    instead.

- **`DOMTokenList.toggle(token)`**
  *What it is:* a real method that adds a class name if it's missing, or
  removes it if it's already present — the exact real mechanism behind
  this lesson's own on/off highlight.
  *Implementation:* per MDN's own documentation, fetched and quoted this
  session, the method "removes an existing token from the list and
  returns `false`. If the token doesn't exist it's added and the function
  returns `true`." Its own real return value is "a boolean value, `true`
  or `false`, indicating whether `token` is in the list after the call or
  not."
  *Its use:* this lesson's own real code calls it with the literal
  string `"highlighted"`, on every real click, letting one line of code
  handle both turning the highlight on and turning it back off.
  - *Type:* an instance method, defined on `DOMTokenList`.
  - *Responsibility:* keep exactly one class name's presence in sync with
    however many times this method has been called for it — present
    after an odd number of calls, absent after an even number.
  - *Depends on:* being called on a real `DOMTokenList` (`entryList
    .classList`, above), and one real string naming the class to toggle.
  - *Connects to:* called on the object `entryList.classList` returned;
    its own real effect — adding or removing `"highlighted"` from
    `entryList`'s actual `class` attribute — is what this lesson's own
    new CSS rule, below, then renders visibly.
  - *Shape:* the real, final link in this lesson's own chain — the one
    call that actually changes something a reader can see, at the end of
    a chain that started with `document`.

### SE Lens

The principle is **the DOM as a live, separate copy of the page — not
the source file that started it.** `getElementById` doesn't read
`index.html` off disk; it searches the browser's own in-memory tree,
built once when the page loaded and free to diverge from the file that

and it would throw away every change any earlier script already made,
since a freshly re-parsed document reflects only the original file, not
the live page a reader is actually looking at. The DOM exists precisely
so a page's own state — including changes JavaScript itself made — stays
queryable without ever touching the file system again.

### SE Lens

The principle is **inversion of control** — this project's own code
never asks "has anything happened yet?" in a loop; it registers what to
do and then hands control to the browser's own event loop, which decides
when, or whether, to call back in. The real alternative not chosen: a
script could, in principle, run a loop continuously checking the mouse's
own position and button state, comparing it against `entryList`'s own
screen coordinates every iteration. The real, concrete cost that
alternative would introduce: a real, continuously-running loop consumes
CPU constantly, whether or not a reader ever clicks anything, and would
have to reimplement, by hand, every real edge case the browser's own
event system already handles correctly (nested elements, disabled
elements, the exact moment a button is considered "pressed"). This
lesson's own single `addEventListener` call defers all of that to code
already written, tested, and shipped inside the browser itself.
