## Terms used in this lesson

- **Object literal** — JavaScript's own real syntax for writing a
  brand-new object directly in code: curly braces holding
  `key: value` pairs, separated by commas. It exists so a group of
  related facts — a title, a category, a duration — can be built and
  handed around as one single real value, instead of as several
  separate variables a program would have to keep in sync by hand.
- **Array literal** — JavaScript's own real syntax for writing a
  brand-new, ordered list of values directly in code: square brackets
  holding comma-separated entries. It exists because `Data` was never
  really *one* record — it's three, and a program needs a real way to
  hold "all of them, in order" as a single value too, not three
  separately-named constants nothing connects to each other.
- **Property** — one real `key: value` pair inside an object; `title`,
  in `{ title: "Morning Run" }`, is a property name, and `"Morning Run"`
  is that property's own real value.
- **Dot notation** — the real syntax `object.property` for reading a
  named property back out of an object, used when the property's own
  name is already known and written directly in the code (`entries[0]
  .title`, later in this lesson).
- **Bracket notation (array index)** — the real syntax `array[index]`
  for reading one real element out of an array by its real, numeric
  position, counting from `0` for the first element — not `1`, a real,
  common source of off-by-one mistakes for anyone new to it.
