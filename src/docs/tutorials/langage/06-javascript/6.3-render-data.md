## Terms used in this lesson

- **`for...of` loop** — a real JavaScript loop that runs its own body
  once for every value in an array (or any other iterable), in order,
  binding each one in turn to a named variable — without a script ever
  having to manage a numeric counter by hand, unlike, for example, a
  classic C-style `for (let i = 0; i < entries.length; i++)` loop.
- **Template literal** — a real JavaScript string written with
  backticks (`` ` ``) instead of quotes, allowing a real expression
  inside `${ }` to be evaluated and inserted directly into the string.
  `` `${entry.duration} minutes` ``, later in this lesson, is one.

## Objects and methods used

- **`document.createElement(tagName)`**
  *What it is:* a real method that builds a brand-new element, of a
  given tag name, that doesn't yet belong anywhere in the page.
  *Implementation:* per MDN's own documentation, fetched and quoted this
  session, the method "creates a new `HTMLElement` that has the
  specified `localName`," and "the new `Element`" is its own real return
  value.
  *Its use:* this lesson's own real code calls it three times per record
  — once for the `<article>`, once for each `<h3>`/`<data>` — building
  every real piece of markup this lesson generates from nothing but a
  tag name.
  - *Type:* an instance method, called on `document`.
  - *Responsibility:* construct one brand-new, real element of the given
    kind, fully valid and ready to be configured, but not yet attached
    anywhere in the visible page.
  - *Depends on:* a single real string naming the element's own tag.
  - *Connects to:* called on `document`; its own real return value is
    what every other method in this lesson's own Objects and methods
    section is then called on, before that element is finally handed to
    `appendChild`.
  - *Shape:* the real starting point of this lesson's own entire "data →
    DOM" pipeline — nothing can be attached to the page until it exists
    as a real object first.

- **`Element.setAttribute(name, value)`**
  *What it is:* a real method that sets one real, named attribute on an
  element, the identical kind of name/value pair Lesson 5.1 first
  defined for hand-written HTML.
  *Implementation:* per MDN's own documentation, fetched and quoted this
  session, the method "sets the value of an attribute on the specified
  element. If the attribute already exists, the value is updated;
  otherwise a new attribute is added with the specified name and value."
  Its own real `value` parameter, per that same documentation, accepts "a
  trusted type or string," and "a specified non-string value... is
  converted automatically into a string" — the real reason this lesson's
  own numeric `entry.id` and `entry.duration` can be passed directly,
  with no manual conversion.
  *Its use:* this lesson's own real code uses it to give each generated
  `<article>` its own real `data-entry-id`, and each generated `<data>`
  element its own real machine-readable `value` — the identical two real
  attributes Lesson 5.8 and Lesson 5.2 already established by hand.
  - *Type:* an instance method, defined on `Element`.
  - *Responsibility:* set exactly one named attribute to exactly one
    given value on the element it's called on, creating the attribute if
    it's absent, overwriting it if it's already present.
  - *Depends on:* being called on a real element, plus a real attribute
    name and a real value to assign it.
  - *Connects to:* called directly on the elements `createElement`
    returned; its own real effect is later inspectable through this same
    real `--dump-dom` tool this whole curriculum has used since Lesson
    5.1.
  - *Shape:* the real, direct JavaScript equivalent of typing an
    attribute by hand inside an opening HTML tag — one real API standing
    in for what Lesson 5.1 through 5.8 all did with a text editor.

- **`Node.textContent`**
  *What it is:* a real, writable property giving script access to an
  element's own text, read or replaced as one plain string.
  *Implementation:* per MDN's own documentation, fetched and quoted this
  session, the property "represents the text content of the node and its
  descendants" — writing to it, specifically, replaces every existing
  child of the element with one single real text node holding the
  assigned string.
  *Its use:* this lesson's own real code writes to it directly —
  `heading.textContent = entry.title;`, for instance — putting each
  record's own real title, and, later, its own `<data>` values, directly
  into newly-built elements with no separate step to create a text node
  by hand.
  - *Type:* an instance property, defined on `Node`, inherited by every
    element.
  - *Responsibility:* represent — and, when assigned, replace — all of
    an element's own text, ignoring any distinction between multiple
    child elements a more surgical API might preserve.
  - *Depends on:* being read or written on a real node.
  - *Connects to:* written here on elements `createElement` just
    returned, immediately after they're built and before they're
    attached to the page at all.
  - *Shape:* the simplest real way this lesson's own code puts visible
    text into a generated element — used everywhere this lesson needs
    plain text, never where a nested element (this lesson's own `<data>`
    inside a `<p>`) is also required.

- **`Node.appendChild(node)`**
  *What it is:* a real method that attaches one given node as the new
  last child of the element it's called on.
  *Implementation:* per MDN's own documentation, fetched and quoted this
  session, the method "adds a node to the end of the list of children of
  a specified parent node," and itself "returns the newly appended
  node."
  *Its use:* this lesson's own real code uses it repeatedly — nesting a
  built `<h3>` inside a built `<article>`, and, at the very end of each
  real iteration, nesting that whole `<article>` inside `entryList`
  itself, the real element Lesson 6.1 already found.
  - *Type:* an instance method, defined on `Node`.
  - *Responsibility:* attach exactly one given node as the parent's own
    new last child, moving it out of wherever it previously was (if
    anywhere) in the process.
  - *Depends on:* being called on a real node intended as the parent,
    plus a single real node to attach.
  - *Connects to:* called here on elements this lesson's own code just
    built with `createElement`; its final real call in this lesson,
    `entryList.appendChild(article)`, is what actually makes each real
    record visible on the page at all.
  - *Shape:* the real, final step connecting a freshly built element,
    otherwise invisible and unattached, to the live document a reader
    can actually see.

- **`Element.append(...nodesOrStrings)`**
  *What it is:* a real, newer sibling of `appendChild`, able to accept
  more than one argument, and, unlike `appendChild`, able to accept
  plain strings directly, not only real nodes.
  *Implementation:* per MDN's own documentation, fetched and quoted this
  session, the method "inserts a set of `Node` objects or strings after
  the last child of the `Element`," accepting any number of arguments,
  mixed freely between the two kinds.
  *Its use:* this lesson's own real code calls it with two arguments at
  once — a plain string, `"Category: "`, and a real `<data>` element —
  building a `<p>` whose own content is part plain text, part nested
  element, in one single real call.
  - *Type:* an instance method, defined on `Element`.
  - *Responsibility:* insert every one of its own given arguments, in
    the order given, as new children (wrapping any plain string in a
    real text node automatically) after whatever children the element
    already had.
  - *Depends on:* being called on a real element, plus one or more real
    strings or nodes to insert.
  - *Connects to:* called here on `<p>` elements this lesson's own code
    just built; the real `<data>` element passed as its second argument
    was itself just fully configured by this same Concept Unit's own
    earlier lines.
  - *Shape:* the one real method in this lesson able to mix plain text
    and a real nested element together in a single call — everywhere
    else in this lesson, `textContent` alone is enough, precisely
    because those elements never need both at once.

- **`Element.classList`** (reappearing from Lesson 6.1)
  *What it is:* per Lesson 6.1's own real entry, restated here in full: a
  real, read-only property giving script access to an element's own
  `class` attribute as a structured collection, not a single string to
  parse by hand.
  *Implementation:* per MDN's own documentation, already quoted in
  Lesson 6.1: "contains a live `DOMTokenList` collection representing
  the `class` attribute of the element."
  *Its use:* this lesson's own real code reads it on a freshly built
  `<data>` element, immediately before adding a class to it — the first
  time this project reads `classList` on anything other than `entryList`
  itself.
  - *Type:* a read-only instance property, defined on `Element`.
  - *Responsibility:* expose whatever element it's read on own `class`
    attribute as a real, structured `DOMTokenList`.
  - *Depends on:* being read on a real element — here, a `<data>`
    element this lesson's own code just built, still entirely unattached
    to the page.
  - *Connects to:* reads from the `<data>` element's own (currently
    absent) `class` attribute; its own real return value is what
    `.add()`, immediately below, is called on.
  - *Shape:* the identical real structured view onto `class` Lesson 6.1
    already established — reused here on a different, newly-built
    element instead of on `entryList`.

- **`DOMTokenList.add(token)`**
  *What it is:* a real method that adds a given class name to an
  element's own `class` attribute.
  *Implementation:* per MDN's own documentation, fetched and quoted this
  session, the method "adds the given tokens to the list, omitting any
  that are already present."
  *Its use:* this lesson's own real code calls it with the literal
  string `"category"`, giving each generated `<data>` element holding a
  category the class this lesson's own new CSS rule (below) needs to
  find it.
  - *Type:* an instance method, defined on `DOMTokenList`.
  - *Responsibility:* ensure a given class name is present in the list,
    adding it if it wasn't already there, doing nothing if it was.
  - *Depends on:* being called on a real `DOMTokenList`, plus one real
    string naming the class to add.
  - *Connects to:* called on the `<data>` element's own `classList`,
    just read above; its own real effect is what this lesson's own new
    `.category` CSS rule then selects.
  - *Shape:* unlike Lesson 6.1's own `.toggle`, a one-directional,
    idempotent operation — calling it twice in a row has the identical
    real effect as calling it once, which is exactly the real behavior
    this lesson needs, since each `<data>` element is only ever built,
    and only ever given this class, one single time.
