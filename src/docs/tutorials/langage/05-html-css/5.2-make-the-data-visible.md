## Terms used in this lesson

- **Attribute** — per Lesson 5.1's own Terms entry, restated here in
  full because this lesson's own real code depends on it again: a
  name/value pair written inside an element's own opening tag, supplying
  extra information about that specific element without changing what
  kind of element it is. This lesson's own second Concept Unit puts a
  new attribute, `value`, to real use.
- **Element** — per Lesson 5.1's own Terms entry, restated here in full:
  the basic structural unit of HTML, a named, possibly-nested unit of
  content. Both real elements this lesson adds — `<article>` and
  `<data>`, both below — are elements in exactly this sense.
- **Heading element (`<h1>`–`<h6>`)** — per Lesson 5.1's own Terms
  entry, restated here in full because this lesson's own real code
  introduces a *second* one: six distinct elements whose own number,
  not any nesting in the markup itself, tells a browser or screen
  reader how deep, in an inferred outline of the whole document, a
  given heading sits. Lesson 5.1 used only `<h1>`, the page's own single
  highest-level heading; this lesson's own real code adds an `<h2>`,
  proving directly, by real screenshot, that the outline this creates is
  not just a machine-readable abstraction — it's visually real too.
- **Paragraph element (`<p>`)** — per Lesson 5.1's own Terms entry,
  restated here in full: a block-level element grouping one real unit of
  running, human-readable text. Lesson 5.1 only ever showed `<p>` inside
  a throwaway lab file; this lesson's own real code is the first time
  `<p>` becomes part of the actual, committed project.
- **`<article>` element** — a real element representing a self-contained
  composition — content substantial and independent enough that it would
  still make sense if pulled out of this page and shown somewhere else
  entirely (a syndicated feed, a search result). MDN's own documentation,
  fetched and quoted this session, names this lesson's own exact use
  case directly, among its own list of qualifying real-world examples:
  "a forum post, a magazine or newspaper article, or a blog entry, **a
  product card**, a user-submitted comment... or any other independent
  item of content." It exists so a browser, a search engine, or a future
  piece of software can find and handle one real, complete `Data`
  record on its own, without needing to understand the rest of the page
  around it.
- **Machine-readable content** — content whose real, exact value a
  program can read and use directly, without first having to guess
  which part of a sentence written for a human is the actual data and
  which part is just descriptive framing around it ("Category:", in
  this lesson's own real code, is framing; "Cardio" is the value). This
  lesson's own second Concept Unit gives this idea a real, dedicated
  element, below.
- **`<data>` element** — a real element linking one piece of human-
  readable content to a separate, explicit machine-readable version of
  the identical value. MDN's own documentation, fetched and quoted this
  session, states its real job plainly: "The `<data>` element links a
  given piece of content with a machine-readable translation." It
  exists so that a value's own real, canonical form (a plain number, a
  fixed category code) can be attached to whatever human-friendly text
  actually gets displayed, without the two ever needing to be the same
  string.
- **`value` attribute (on `<data>`)** — per this lesson's own Terms
  entry for **Attribute**, applied here specifically: the attribute
  `<data>` uses to hold that machine-readable version. MDN's own
  documentation, fetched and quoted this session, states its real
  contract directly: "This attribute specifies the machine-readable
  translation of the content of the element."
