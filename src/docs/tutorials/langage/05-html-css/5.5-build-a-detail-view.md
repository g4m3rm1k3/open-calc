## Terms used in this lesson

- **Attribute** — per Lesson 5.1's own Terms entry, restated here in
  full: a name/value pair inside an element's own opening tag. This
  lesson's own real code adds a new one, `class`, below.
- **`<section>` element** — per Lesson 5.4's own Terms entry, restated
  here in full: a real element representing a generic, standalone
  section of a document, carrying real thematic meaning rather than
  existing only as a styling wrapper. This lesson's own real code adds
  a *second* one, sibling to the first.
- **`<article>` element** — per Lesson 5.2's own Terms entry, restated
  here in full: a real, self-contained composition. This lesson's own
  real code reuses the identical real shape a fourth time, inside the
  new section this lesson adds.
- **`class` attribute** — a real, global HTML attribute holding one or
  more real, author-chosen names, used by CSS (via the class selector,
  below) and JavaScript (Phase 6, not yet written) to target specific
  elements that a plain element-type selector like `section` or
  `article` would otherwise treat identically to every other element of
  the same real type.
- **Class selector (`.detail`)** — a real CSS selector matching every
  real element whose own `class` attribute contains the given name.
  MDN's own documentation, fetched and quoted this session, states its
  real definition directly: "The CSS class selector matches elements
  based on the contents of their `class` attribute." It exists,
  per that same documentation, because a plain type selector like
  `article` (Lesson 5.4) "target[s] all elements of a particular type,"
  while "class selectors allow you to apply styles to specific elements
  regardless of their type" — exactly this lesson's own real problem:
  distinguishing *this specific* `<article>` from the three others
  already on the page, all four sharing the identical real element type.
- **Cascade** — the real, defined algorithm a browser uses to decide
  which declaration actually applies when more than one real CSS rule
  matches the same element for the same property. MDN's own
  documentation, fetched and quoted this session, names it directly:
  "The cascade is an algorithm that defines how user agents combine
  property values originating from different sources." It exists
  because this lesson's own real code, below, has two separate rules
  both matching the identical real `<article>` — `article` (Lesson 5.4)
  and `.detail article` (this lesson's own new rule) — and only one
  real, defined outcome can actually apply.
- **Specificity** — the real, calculated weight the cascade uses to
  choose between two competing rules that both match the same element,
  when neither one is otherwise more important. MDN's own documentation,
  fetched and quoted this session, states the real rule this lesson's
  own code directly depends on: a selector's own specificity is counted
  per real category — "For each type... in a matching selector, add
  0-0-1"; "For each class... add 0-1-0" — and "the selector with the
  greater value in the CLASS column wins, no matter the value in the
  TYPE column." This lesson's own two competing selectors, `article`
  (one type, `0-0-1`) and `.detail article` (one class plus one type,
  `0-1-1`), are real, calculated proof of exactly this rule.

## Concept Unit: The Cascade — Recomposing the Same Shape's Own Real Look
