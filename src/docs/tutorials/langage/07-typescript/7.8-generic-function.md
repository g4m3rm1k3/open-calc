## Terms used in this lesson

- **Generic function** — a real function (or type) parameterized not
  just by its own ordinary values, but by a *type itself*, written
  `<T>` directly after the function's own name. It exists so one real
  function body can be written once and reused, unchanged, across
  genuinely different real types — `firstOf<T>`, this lesson's own
  first real example, works identically for a real array of numbers or
  a real array of strings, with `T` standing in for whichever one a
  given real call actually uses.
- **Type parameter** — the real `T` itself (or any other real name
  chosen for it) — a placeholder standing for whatever real type a
  specific real call site supplies, resolved fresh at every real call,
  the same real relationship an ordinary parameter has to the real
  values passed to it, one level up.
- **Constraint** — a real, optional restriction on a type parameter,
  written `<T extends SomeShape>`, narrowing `T` from "any type at
  all" down to "any type that at least has this real shape." It exists
  because a genuinely unconstrained `T` carries no real, known
  properties at all — a generic function's own body can't read
  `item.id` off a value of type `T` unless something has promised every
  real `T` actually has one.

## Concept Unit: A Promise Every T Must Keep

### The Problem

`renderEntries`/`createEntryElement`'s own real, committed shape —

```ts
function renderList<T>(container: HTMLElement, list: T[], toElement: (item: T) => HTMLElement): void {
  for (const item of list) {
    const element = toElement(item);
    element.setAttribute("data-entry-id", String(item.id));
    container.appendChild(element);
  }
}
```
