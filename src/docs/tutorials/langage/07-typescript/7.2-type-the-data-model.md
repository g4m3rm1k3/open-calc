## Terms used in this lesson

- **Object type** — a real type describing the shape of an object: which
  named properties it must have, and what type each one holds. It
  exists because a value can be more than one primitive at once — a
  real `Data` record is a whole cluster of related fields, and nothing
  so far has ever named that cluster as one real, checkable thing.
- **`interface`** — the specific real TypeScript keyword this lesson
  uses to declare an object type: `interface Entry { ... }`. TypeScript
  offers a second, real way to write the same idea (`type Entry =
  {...}`); this lesson doesn't yet explain that second form or the real
  difference between the two — Lesson 7.4, later in this phase, covers
  that directly.
- **Optional property** — a property, marked with a trailing `?`
  immediately after its own name (`duration?: number`), that a real
  object matching this type is allowed to leave out entirely. It exists
  because not every real field on a real object type is genuinely
  always present — forcing every property to be required would make an
  honest type impossible to write for data that's sometimes
  incomplete.
- **Structural typing** — TypeScript's own real rule for deciding
  whether a given object actually counts as an `Entry`: judged purely
  by *shape* — does it have the right real properties, with the right
  real types — never by whether it was built with any particular class,
  or declared with any explicit "this is an `Entry`" marker anywhere.
  It exists as a deliberate, different real design choice from this
  whole curriculum's own C#, Java, and Kotlin phases, where an object
  only counts as a given type if it was built from a class that
  actually, explicitly extends or implements it — a real difference
  this lesson's own CS Lens, below, explores directly.
- **`undefined`** — reappearing from this whole curriculum's own
  earliest JavaScript lessons: JavaScript's own real, built-in value
  meaning "no value was ever assigned here." An optional property that's
  genuinely left out of a real object reads back as this exact real
