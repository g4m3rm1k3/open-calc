## Terms used in this lesson

- **Non-null assertion** — a real, single `!` written directly after an
  expression whose own declared type includes `null` (or `undefined`),

  null here" — checked by nothing, enforced by nothing, purely a real,

  Lesson 7.1's own: instead of working out a value's type from its own

  introduction: explicit `: Type` syntax, written by a human, checked

### SE Lens

The principle is **an assertion moves a real guarantee from "provable
by the compiler" to "trusted from the human who wrote it"** — real,
useful exactly when a human genuinely knows more than the type system
can see (`index.html`'s own hardcoded markup, here), and real,
dangerous the moment that knowledge turns out to be wrong: if a future
real edit ever removed `id="entry-list"` from `index.html`, this
lesson's own real `!` would keep compiling cleanly, right up until the
real page actually threw a real runtime error the instant `entryList`
turned out to be `null` after all — the exact real class of bug
TypeScript's own null-checking exists to prevent, silenced, on purpose,
at exactly one real, deliberate spot. The real alternative — a genuine
`if (!entryList) throw new Error(...)` guard, immediately after the
real lookup — costs one real, extra line and keeps the check live at
runtime too, catching the real mistake this lesson's own `!` would
silently let through; this lesson chooses the assertion anyway, on the
honest, real grounds that `index.html` and `app.ts` are committed
together, in the same real repository, and drifting apart undetected is
a genuinely low real risk for a project this size.
