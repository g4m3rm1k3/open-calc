## Terms used in this lesson

- **Type guard** — a real, ordinary runtime check — here, `entry
  .duration !== undefined` — written in code a reader would recognize
  regardless of TypeScript, that TypeScript *also* understands well
  enough to track a variable's own type differently on either side of
  it. It exists because checking a real value at runtime and knowing
  its real type at compile time have always been two separate real
  concerns — a type guard is the one real place they meet.
- **Control-flow narrowing** — what TypeScript actually does once it
  recognizes a real type guard: inside the guarded branch, it treats
  the checked value as having a real, smaller type than its own,
  outer, declared one — `entry.duration`, declared `number |
  undefined`, is narrowed to plain `number` inside this lesson's own
  real `if` block. It exists because a value's own declared type is
  necessarily the *widest* real possibility across its whole real
  scope; narrowing lets code that has already proven a real, smaller
  possibility use that proof, rather than being stuck with the widest
  case everywhere.

```ts
console.log(describe({}));
```
