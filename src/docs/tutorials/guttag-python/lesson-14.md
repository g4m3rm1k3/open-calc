# Lesson 14: Modules and Packages — `import` and the Standard Library

The reader will import modules, use the most important standard library modules (`math`, `random`, `os`, `sys`, `datetime`), write their own module, and understand `if __name__ == '__main__'`. The transferable problems this lesson addresses are: (1) a module is just a `.py` file — any `.py` file can be imported; (2) the standard library gives you most of what you need without installing anything; and (3) `if __name__ == '__main__'` lets a file work both as a script and as an importable module without running unintended code.

**What you need to know first:** Lessons 0–13 (REPL, all types, variables, conditionals, iteration, functions, all data structures, comprehensions, higher-order functions, recursion).

### Terms used in this lesson

- **`import`** — a keyword that loads a module into the current namespace, giving you access to its contents. It solves the problem of needing to write all your code in one massive file.
- **`from`** — a keyword used alongside `import` to bring specific names from a module directly into the current namespace, letting you use them without the module prefix.
- **`as`** — a keyword used to create an alias for an imported module or name, which saves typing or avoids naming conflicts.
- **module** — simply a `.py` file containing Python code. It serves as a container for related variables, functions, and classes.
- **namespace** — a mapping from names to objects. Importing a module keeps its names in their own namespace to prevent accidental collisions with your variables.
- **pseudo-randomness** — a sequence of numbers that appears random but is generated by a deterministic algorithm. It allows for reproducible randomness in testing and simulation.
- **`def`** — a keyword that defines a new function.
- **`return`** — a keyword that ends a function's execution and hands a value back to the caller.
- **f-string** — a string literal prefixed with `f` that allows embedding Python expressions inside curly braces `{}`.
- **`if`** — a keyword used to test a condition and run a block of code only if the condition is true.

### Objects and methods used

- **`math`**
  - *What it is:* A built-in module for mathematical operations.
  - *Implementation:* A standard library module wrapping C mathematical functions.
  - *Its use:* We reach for it to calculate square roots, trigonometry, and logarithms.
  - *Type:* Module.
  - *Responsibility:* Provides access to standard mathematical functions and constants.
  - *Depends on:* Nothing.
  - *Connects to:* Called by our code to perform math computations.
  - *Shape:* A standard library API boundary.

- **`random`**
  - *What it is:* A built-in module for generating pseudo-random numbers.
  - *Implementation:* A standard library module implementing the Mersenne Twister algorithm.
  - *Its use:* We reach for it to pick random choices, shuffle lists, and generate random integers.
  - *Type:* Module.
  - *Responsibility:* Provides functions to generate random numbers and perform random selections.
  - *Depends on:* An initial seed value (which it gets from the system time by default).
  - *Connects to:* Called by our code to introduce non-deterministic behavior.
  - *Shape:* A standard library API boundary.

- **`os`**
  - *What it is:* A built-in module for interacting with the operating system.
  - *Implementation:* A standard library module wrapping OS-specific system calls.
  - *Its use:* We reach for it to work with file paths and directories cross-platform.
  - *Type:* Module.
  - *Responsibility:* Provides a unified interface to operating system functionality.
  - *Depends on:* The underlying operating system (Windows, macOS, Linux).
  - *Connects to:* Our code calls it; it calls the OS kernel.
  - *Shape:* An OS abstraction layer.

- **`sys`**
  - *What it is:* A built-in module for interacting with the Python runtime environment.
  - *Implementation:* A standard library module providing access to interpreter state.
  - *Its use:* We reach for it to get command-line arguments and check the Python version.
  - *Type:* Module.
  - *Responsibility:* Exposes variables and functions that interact strongly with the interpreter.
  - *Depends on:* The Python interpreter instance.
  - *Connects to:* Exposes runtime state to our script.
  - *Shape:* An interpreter API boundary.

- **`datetime`**
  - *What it is:* A built-in module for manipulating dates and times.
  - *Implementation:* A standard library module containing classes for date/time math.
  - *Its use:* We reach for it to represent timestamps, calculate durations, and format dates.
  - *Type:* Module.
  - *Responsibility:* Provides robust objects for date and time arithmetic and formatting.
  - *Depends on:* Nothing for basic math; system clock for current time.
  - *Connects to:* Called by our code to model temporal data.
  - *Shape:* A standard library API boundary.

- **`__name__`**
  - *What it is:* A special built-in variable assigned by Python to every module.
  - *Implementation:* A string automatically set by the interpreter.
  - *Its use:* We check if it equals `'__main__'` to see if our file was run directly.
  - *Type:* String variable.
  - *Responsibility:* Identifies the context in which a module is executing.
  - *Depends on:* The interpreter loading the file.
  - *Connects to:* Read by our script's conditional logic.
  - *Shape:* An interpreter-injected variable.

## Concept Unit: `import` — three forms

### The Problem

We want to use functions that aren't built into Python's core, but we don't want every possible function loaded into memory at once, and we don't want naming conflicts. How do we pull in extra tools selectively?

### Introduce the concept in isolation

Here is a throwaway script demonstrating the three main forms of importing the `math` module.

```python
import math
print(math.sqrt(16))

from math import sqrt, pi
print(sqrt(16))
print(pi)

import math as m
print(m.sqrt(25))
```

Output:
```text
4.0
4.0
3.141592653589793
5.0
```

This is called **importing**. It proves that `import math` keeps the namespace clean (requiring `math.sqrt`), `from math import sqrt` brings the name directly in, and `import math as m` creates an alias.

This introduces the **`random` module**. Setting a seed with `random.seed(42)` ensures the pseudo-random sequence is reproducible. It proves we can get random floats, integers, choices, and even shuffle lists in-place.

## Concept Unit: `if __name__ == '__main__'` — the module/script duality

### The Problem

We want to add some code at the bottom of `my_utils.py` to test the `square` function, but we *don't* want that test code to run automatically every time another file does `import my_utils`.

### Introduce the concept in isolation

Here is a throwaway script demonstrating the duality.

```python
# my_utils_test.py
print(f"My name is {__name__}")

if __name__ == '__main__':
    print("I am running directly!")
```

If we run `python my_utils_test.py`, the output is:
```text
My name is __main__
I am running directly!
```

If another file imports it via `import my_utils_test`, the output is:
```text
My name is my_utils_test
```

This introduces the **`__name__ == '__main__'` guard**. It proves that Python sets `__name__` to `'__main__'` only when a file is executed directly.

### Mechanical walkthrough

- `if`: Keyword to start a conditional branch.

- `:`: Ends the `if` statement.
- `print(square(7))`: Calls our custom function and prints the result, only if the guard condition is met.
