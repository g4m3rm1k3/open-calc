## The standard — read this before every lesson

From the contract:

**The single test:** Could a student skim this lesson, find the formula, and move on without losing anything? If yes — it is a reference document, not a lesson.

**Earn every symbol AND every word.** Every technical term is introduced in three steps: plain English first, then the name with an explanation of what it means and why mathematicians use that word, then use it as a shorthand from then on.

**Multiple angles on every idea.** Geometric intuition first, then algebraic proof, then numerical check. A concept explained one way has been stated. Explained three ways it has been taught.

**Take time with every idea.** One description, no explanation, one example = a reference entry = failure. There is no "too long" if the length is genuine teaching.

**Code: smallest runnable unit.** If a block can be split with explanation in between, split it. One point per block. One output per block. Functions called once. ~20 lines max. Output ≤ 12 lines.

**All visuals: Python matplotlib only.** JavaScript canvas does not render in this app.

## How to write each lesson

1. Ask: what is the one thing the student cannot do yet? What gap does this lesson fill?
2. Find the entry point — something the student already knows that connects to this idea.
3. Write the opening sentence. Does it create curiosity? If not, start again.
4. Build toward the idea. The student should arrive at it before you state it.
5. Name it. Explain the name. Then use it.
6. Come at it from a second angle — geometry, or a specific worked example, or code.
7. Prove or derive everything. No "it can be shown."
8. End with a non-trivial challenge and one sentence pointing to the next lesson.

Write the whole lesson before moving to the next one. Do not plan ahead — just write.
