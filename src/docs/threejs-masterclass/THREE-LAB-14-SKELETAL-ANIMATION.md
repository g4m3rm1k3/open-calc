# eCaM v2 — LAB 14 — Skeletal Animation (Bones)

This lab introduces the concept of rigging and animating organic shapes. While CAD software uses rigid Forward Kinematics (like our robot arm), game characters use Skinning.

**What this lab adds:**

- `THREE.SkinnedMesh`.
- Vertex Weights (Skinning).

## What You Will Build

You will understand the mathematical difference between a rigid CAD assembly and a deformable human character. We won't write the massive vertex weight arrays manually (they are always generated by Blender), but you will learn how the data structures operate under the hood.

---

### Concept: Skeletal Rigging (`THREE.Bone`)

**What it is:** A `Bone` is a specialized `Group` that acts as an invisible pivot point. An interconnected hierarchy of bones (e.g., Spine -> Shoulder -> Elbow -> Wrist) is called an Armature or Skeleton.

**The problem before:** If you want a character to bend its elbow, you can't just rotate the forearm mesh. The skin around the elbow needs to stretch and fold. A solid `Mesh` cannot bend.

**The solution:** You build the geometry of the arm as a single continuous tube (`SkinnedMesh`). Then you build an invisible skeleton inside it. You link the vertices of the tube to the bones. When the bone moves, it mathematically pulls the vertices with it.

---

### Concept: Vertex Weights (Skinning)

**What it is:** Two specific `BufferAttributes` attached to your geometry: `skinIndex` and `skinWeight`. 

**The problem before:** If an elbow bone rotates 90 degrees, which vertices should move? Just the forearm? What about the skin directly ON the elbow joint? It needs to move 45 degrees, half-following the upper arm and half-following the forearm.

**The solution:** Every single vertex is mathematically attached to up to 4 bones simultaneously.
- `skinIndex`: Which bones influence this vertex? (e.g., Bone 1 [Upper Arm], Bone 2 [Forearm]).
- `skinWeight`: How much does each bone pull? (e.g., 50% Bone 1, 50% Bone 2).

The GPU calculates the final position of the vertex by averaging the transformations of the bones based on these weights.

**Why it matters here:** If you import a character and it looks like a spiked monster when it walks, the vertex weights are corrupted. This happens frequently when exporting from Blender if the weight painting wasn't perfectly normalized to 1.0.

## Step 1 — Inspecting a SkinnedMesh Structure

Because manually typing `Float32Arrays` for skin indices is virtually impossible, let's write a mock function that simulates what the `GLTFLoader` gives you when you import a character.

Open `main.js`. Below your asset loading code, add this:

```js
// ── Skeletal Animation Concepts ──────────────────────────────────────────────

function simulateCharacterImport() {
  // 1. The Skeleton
  // Bones are just objects in a hierarchy.
  const shoulderBone = new THREE.Bone();
  const elbowBone = new THREE.Bone();
  
  // The elbow is a child of the shoulder. If the shoulder moves, the elbow moves.
  shoulderBone.add(elbowBone); 
  elbowBone.position.y = 5; // The elbow is 5 units below the shoulder
  
  // Create a Skeleton object to manage the array of bones
  const skeleton = new THREE.Skeleton([shoulderBone, elbowBone]);

  // 2. The Skin
  // (In reality, this geometry has massive skinIndex/skinWeight BufferAttributes attached)
  const armGeometry = new THREE.CylinderGeometry(1, 1, 10, 16);
  const armMaterial = new THREE.MeshStandardMaterial({ color: 0xffccaa });
  
  // 3. The SkinnedMesh
  // A special Mesh type that knows how to read the skin weights and bend the geometry on the GPU.
  const characterArm = new THREE.SkinnedMesh(armGeometry, armMaterial);
  
  // Bind the invisible skeleton to the visible mesh
  characterArm.add(shoulderBone); // The mesh must contain the root bone
  characterArm.bind(skeleton);
  
  return { mesh: characterArm, bones: skeleton.bones };
}

const mockCharacter = simulateCharacterImport();
mockCharacter.mesh.position.set(5, 5, 0);
scene.add(mockCharacter.mesh);

// Optional: Add a SkeletonHelper to make the invisible bones visible!
const skeletonHelper = new THREE.SkeletonHelper(mockCharacter.mesh);
scene.add(skeletonHelper);
```

### SAVE AND TRY

Save. Open the app.

You should see: A tall cylinder representing an arm, and colored lines drawing a pyramid-like shape inside it. That shape is the `SkeletonHelper` showing you exactly where the invisible bones are.

In DevTools Console, type:
  `mockCharacter.mesh.isSkinnedMesh`
Expected: `true`
