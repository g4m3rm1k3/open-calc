# Concepts Glossary — Index of `concepts/`

One line per real concept file: its name, its own title, and its own
"What you'll understand by the end" sentence, verbatim from the file
itself. Generated directly from the real files — not hand-summarized —
so nothing here says anything a file doesn't already say about itself.

**How to use this:** when a build/lesson plan needs to resolve a
glossary entry against the catalog, check *this* file first instead of
opening every plausibly-named candidate file. It turns "read N candidate
files" into "scan one list, then open only the real, remaining
candidates." It does **not** replace actually reading a candidate file
before citing it — `PLANNING_PASS_CHECKLIST.md`'s own rule still
applies in full: *never assert a match by filename (or by this
glossary's one-line summary) alone.* A name or summary that sounds
right is a reason to open the real file next, not a reason to skip
doing so.

**Keeping this current:** regenerate (or append to) this file whenever
a new concept file is added or an existing one's own title/description
line changes. It's a derived index, not a second source of truth — the
real files are always authoritative if this ever drifts out of sync.
