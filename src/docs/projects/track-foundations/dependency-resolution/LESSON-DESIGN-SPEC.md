## 1. `L0a-1-classes-and-objects`

**Derived from:** `track/` Lesson 0

A blueprint describing what fields and methods every object built from it will have — the template objects are constructed from. (anchor concept: `class`)

**Concepts introduced:**

- `class` — Class
- `nested-class` — Nested Class
- `object` — Object
- `object-creation` — Object Creation (Instantiation)

**Concepts exercised (reused from earlier lessons):**

- (none)

**Prerequisites (must be taught by an earlier lesson):**

- (none — resolves directly to the Learner Baseline)

**Why this lesson exists:**

- `track/Lesson 0` explicitly lists "what a class is, in its plain form" as assumed prior knowledge, never taught by `track/` itself at all — a real gap the graph's own validator caught (14 later nodes required `class` before this node existed). A true-beginner reader needs this taught from scratch, not silently assumed.
- Java uses this constantly (`InventoryAdapter.InventoryViewHolder`, Lesson 6) where Python rarely nests classes at all.
- Needed before "class-level state" can be meaningfully contrasted against "each object gets its own."
- The literal first step behind every `new InventoryActivity()`, `new Item(...)`, and `new Intent(...)` in this course — never itself named as its own concept before now.

## 5. `L0a-5-inheritance-and-polymorphism`

**Derived from:** `track/` Lesson 0

**Concepts introduced:**

- `dynamic-dispatch` — Dynamic Dispatch
- `inheritance` — Inheritance
- `method-overriding` — Method Overriding
- `runtime-type-narrowing` — Runtime Type Narrowing
- `sealing-a-type-or-method` — Sealing a Method or Class

**Concepts exercised (reused from earlier lessons):**

- (none)

**Prerequisites (must be taught by an earlier lesson):**

- `method` — satisfied by `L0a-2-members` (lesson #2 in this order)
- `object` — satisfied by `L0a-1-classes-and-objects` (lesson #1 in this order)

**Why this lesson exists:**

- Same Java keyword as `immutability` but a genuinely different guarantee (behavior can't be replaced vs. a value can't change) — worth separating so the two meanings aren't conflated.

- Room refuses to run a query directly on this thread at all, and `RecyclerView` refuses to be updated from any other thread — both are the same underlying rule, encountered from two directions.
- Background database work (Lesson 13) can safely read/write the database, but must hand results back through this exact mechanism before updating anything on screen.
