# CAD/CAM — Lesson 12 — Extrusion

## What You Will Build

With a closed sketch profile on the XY plane, clicking "Extrude" and typing a depth
creates a 3D solid that appears in the viewport. For a rectangular sketch, a box
shape is extruded. The solid is represented as a triangle mesh with correct face
normals. A feature tree panel lists "Extrusion 1", "Extrusion 2", etc. Clicking a
feature highlights it. The sketch remains visible underneath the solid as a wire
overlay.

## What You Need to Know First

Lessons 01–11. The sketch with lines, circles, and arcs exists. Constraint solving

## The Problem

A sketch is 2D — it lives on the XY plane. Extruding it means sweeping every point
in the sketch profile along the Z axis by the extrusion depth, creating a 3D shape.

The minimal representation of a 3D solid is a **triangle mesh**: a set of vertices
(points in 3D space) and faces (triplets of vertex indices, each forming a triangle).
Every face has a **normal** — a unit vector perpendicular to the face, pointing
outward. The normal determines how the face is shaded by lights.

The CAD term for this operation is a **prismatic extrusion** (or *boss-extrude*) —
the cross-section is constant along the extrusion direction. It is the simplest
3D operation and the most common: most machined parts begin as a 2D sketch extruded
to a height.

## Step 1 — Maths: Extrusion Geometry and Face Normals

### Extruding a polygon

Given a closed polygon with vertices `[V₀, V₁, ..., Vₙ₋₁]` on the XY plane (`z=0`),
and extrusion depth `d`, the extruded solid has:

**Top face** (at `z = 0`): the original polygon, vertices `(x, y, 0)`.
**Bottom face** (at `z = -d`): the same polygon, vertices `(x, y, -d)`.
**Side faces**: for each edge `(Vᵢ, Vᵢ₊₁)` of the polygon, a quad formed by the four
vertices `(Vᵢ,0)`, `(Vᵢ₊₁,0)`, `(Vᵢ₊₁,-d)`, `(Vᵢ,-d)`. Each quad is two triangles.

Extrusion depth is negative Z because Three.js convention has Z pointing toward the
viewer. The material is below the sketch plane (the tool cuts downward in CNC).

### Face normals

A triangle with vertices `A`, `B`, `C` (in counter-clockwise order when viewed from
the outside) has normal:

```
normal = normalise((B - A) × (C - A))
```

The **cross product** `(B - A) × (C - A)` produces a vector perpendicular to the
triangle plane. `normalise` divides by the magnitude to produce a unit vector.

For the top face (looking down from `+Z`), vertices in counter-clockwise order:
the cross product points in `+Z` direction. For the bottom face (looking from `-Z`),
vertices in clockwise order (reversed from top): cross product points in `-Z` direction.

### Triangulating a convex polygon

A convex polygon with `n` vertices can be triangulated as a **fan** from vertex 0:
triangles `(V₀, V₁, V₂)`, `(V₀, V₂, V₃)`, ..., `(V₀, Vₙ₋₂, Vₙ₋₁)`.

This fan triangulation is only valid for **convex polygons**. For concave polygons,
a more complex algorithm (ear clipping, Delaunay) is needed. The lesson uses convex
polygons initially; lesson 14 (sketch on face) introduces ear clipping.

**CS lens — the half-edge mesh:**
A **half-edge mesh** (also called DCEL — Doubly Connected Edge List) is the standard
data structure for boundary representations of 3D solids in production CAD systems.
Each edge is represented as two directed half-edges (one per adjacent face). Each
half-edge stores its origin vertex, the next half-edge around its face, the opposite
half-edge (on the adjacent face), and the face it belongs to. This structure supports
efficient traversal of faces around a vertex, faces adjacent to a face, and edges on
a face boundary.

For this lesson, we use a simpler flat triangle mesh (just vertices and indices)
sufficient for rendering. The full half-edge structure is the architecture that
OpenCASCADE uses and that the Python backend (lesson 15) will implement.

## Step 2 — Extrusion Data Model

### Create `src/scene/solid.ts`

```typescript
export interface SolidVertex {
  x: number
  y: number
  z: number
}

export interface SolidFace {
  vertexIndices: [number, number, number]  // triangle indices
  normalX:       number
  normalY:       number
  normalZ:       number
}

export interface Solid {
  readonly id:       string
  readonly vertices: readonly SolidVertex[]
  readonly faces:    readonly SolidFace[]
  readonly sourceSketchId?: string
}
```

**What `src/scene/solid.ts` is:**
`solid.ts` owns the 3D solid data type. It is separate from the sketch types
(`sketch.ts`) because solids exist in 3D space while sketches are 2D. Solids are
sent to the Python backend in lesson 15 and generated by the toolpath engine in
lessons 21–22.

**`[number, number, number]` — tuple type:**
`vertexIndices: [number, number, number]` is a TypeScript **tuple** — a fixed-length
array with a specific type for each position. A tuple of three numbers means exactly
three vertex indices. TypeScript would reject `[0, 1]` (only two) or `[0, 1, 2, 3]`
(four). Plain arrays `number[]` would allow any length.

## Step 3 — The Extrusion Algorithm

### Create `src/scene/extrude.ts`

```typescript
import type { Sketch }        from './sketch.js'
import type { Solid, SolidVertex, SolidFace } from './solid.js'

let nextSolidId = 0

export function extrudeSketch(
  sketch: Sketch,
  depth:  number,
): Solid | null {
  // Extract the polygon from sketch lines (assumes a single closed loop)
  const orderedVertices = extractClosedLoop(sketch)
  if (orderedVertices === null) return null
  if (orderedVertices.length < 3) return null

  const vertices: SolidVertex[] = []
  const faces:    SolidFace[]   = []

  // Top and bottom vertex layers
  const topStart    = vertices.length
  for (const point of orderedVertices) {
    vertices.push({ x: point.x, y: point.y, z: 0 })
  }
  const bottomStart = vertices.length
  for (const point of orderedVertices) {
    vertices.push({ x: point.x, y: point.y, z: -depth })
  }

  const count = orderedVertices.length

  // Top face (fan triangulation, counter-clockwise from above)
  for (let index = 1; index < count - 1; index++) {
    faces.push({
      vertexIndices: [topStart, topStart + index, topStart + index + 1],
      normalX: 0, normalY: 0, normalZ: 1,
    })
  }

  // Bottom face (fan triangulation, clockwise from above = counter-clockwise from below)
  for (let index = 1; index < count - 1; index++) {
    faces.push({
      vertexIndices: [bottomStart, bottomStart + index + 1, bottomStart + index],
      normalX: 0, normalY: 0, normalZ: -1,
    })
  }

  // Side faces
  for (let index = 0; index < count; index++) {
    const nextIndex = (index + 1) % count
    const topA    = topStart    + index
    const topB    = topStart    + nextIndex
    const bottomA = bottomStart + index
    const bottomB = bottomStart + nextIndex

    // Compute side face normal (perpendicular to the edge, pointing outward)
    const edgeDx = orderedVertices[nextIndex]!.x - orderedVertices[index]!.x
    const edgeDy = orderedVertices[nextIndex]!.y - orderedVertices[index]!.y
    const edgeLen = Math.hypot(edgeDx, edgeDy)
    const normalX =  edgeDy / edgeLen
    const normalY = -edgeDx / edgeLen

    // Two triangles per side quad
    faces.push({ vertexIndices: [topA, topB, bottomA], normalX, normalY, normalZ: 0 })
    faces.push({ vertexIndices: [topB, bottomB, bottomA], normalX, normalY, normalZ: 0 })
  }

  return {
    id:             `solid-${nextSolidId++}`,
    vertices,
    faces,
    sourceSketchId: undefined,
  }
}
```

**`(index + 1) % count` — modular arithmetic:**
`%` is the modulo operator — it gives the remainder after division. `(count - 1 + 1) % count = 0` wraps the last vertex back to the first, closing the polygon loop. Without the modulo, the last edge (from the last vertex to the first) would not be processed.

**Side face normal derivation:**
The outward normal of a vertical side face is perpendicular to the edge and points
away from the interior. The edge direction is `(edgeDx, edgeDy)`. The outward normal
(rotated 90° counter-clockwise from the edge direction) is `(-edgeDy, edgeDx)` /
length. For a polygon wound counter-clockwise, this rotation produces outward normals.

**`extractClosedLoop(sketch)`:**
This function traverses the sketch lines to find a closed polygon — a chain of
connected line segments where the last endpoint connects back to the first.
Implementation: build a map from endpoints to lines, follow the chain starting from
any line, detect when the start point is reached again.

```typescript
function extractClosedLoop(
  sketch: Sketch,
): { x: number; y: number }[] | null {
  if (sketch.lines.length === 0) return null

  // Build adjacency: endpoint string → line
  const TOLERANCE = 1e-6

  function pointKey(x: number, y: number): string {
    return `${x.toFixed(6)},${y.toFixed(6)}`
  }

  const startMap = new Map<string, typeof sketch.lines[0]>()
  for (const line of sketch.lines) {
    startMap.set(pointKey(line.start.x, line.start.y), line)
  }

  const firstLine = sketch.lines[0]!
  const loop: { x: number; y: number }[] = [firstLine.start]
  let   current = firstLine

  for (let step = 0; step < sketch.lines.length; step++) {
    const nextKey  = pointKey(current.end.x, current.end.y)
    const nextLine = startMap.get(nextKey)

    if (nextLine === undefined) return null  // broken chain

    if (
      Math.abs(nextLine.start.x - firstLine.start.x) < TOLERANCE &&
      Math.abs(nextLine.start.y - firstLine.start.y) < TOLERANCE
    ) {
      return loop  // closed loop found
    }

    loop.push(nextLine.start)
    current = nextLine
  }

  return null  // no closed loop
}
```

## Step 4 — Rendering the Solid

### Update `src/viewport/sketchRenderer.ts` (or create a new `solidRenderer.ts`)

```typescript
export function buildSolidMesh(solid: Solid): THREE.Mesh {
  const geometry  = new THREE.BufferGeometry()
  const positions = new Float32Array(solid.faces.length * 3 * 3)
  const normals   = new Float32Array(solid.faces.length * 3 * 3)

  for (let faceIndex = 0; faceIndex < solid.faces.length; faceIndex++) {
    const face    = solid.faces[faceIndex]!
    const offset  = faceIndex * 9

    for (let vertexInFace = 0; vertexInFace < 3; vertexInFace++) {
      const globalVertexIndex = face.vertexIndices[vertexInFace]!
      const vertex            = solid.vertices[globalVertexIndex]!
      const positionOffset    = offset + vertexInFace * 3

      positions[positionOffset]     = vertex.x
      positions[positionOffset + 1] = vertex.y
      positions[positionOffset + 2] = vertex.z

      normals[positionOffset]     = face.normalX
      normals[positionOffset + 1] = face.normalY
      normals[positionOffset + 2] = face.normalZ
    }
  }

  geometry.setAttribute('position', new THREE.BufferAttribute(positions, 3))
  geometry.setAttribute('normal',   new THREE.BufferAttribute(normals,   3))

  const material = new THREE.MeshStandardMaterial({
    color:       0x94a3b8,
    side:        THREE.DoubleSide,
    roughness:   0.7,
    metalness:   0.1,
  })

  const mesh  = new THREE.Mesh(geometry, material)
  mesh.name   = solid.id
  return mesh
}
```

**`THREE.BufferGeometry` with `setAttribute` — first full use:**
`setAttribute('position', new THREE.BufferAttribute(positions, 3))` uploads vertex
positions to the GPU. The `Float32Array` stores interleaved XYZ values: positions[0],
positions[1], positions[2] are the XYZ of the first vertex. The `3` in
`BufferAttribute(positions, 3)` says "each item is 3 floats." Same for normals.

This is the **non-indexed geometry** format: each face's vertices are stored
separately (even if two faces share a vertex, the vertex data appears twice). Indexed
geometry (using a separate index buffer) is more memory-efficient but more complex.
For extrusion output that has simple, small meshes, non-indexed is acceptable.

**`roughness: 0.7, metalness: 0.1`:**
These are PBR (physically-based rendering) parameters. `roughness` controls surface
smoothness (0 = mirror, 1 = fully diffuse). `metalness` controls whether the surface
behaves as a metal (1) or dielectric (0). A solid with `roughness: 0.7, metalness: 0.1`
looks like matte plastic — appropriate for visualising machined stock material.

const [solids, setSolids] = useState<Solid[]>([])

function handleExtrude(depth: number): void {

## Debugging: When Extrusion Produces Incorrect Geometry

**Symptom: solid is visible but faces are black (no shading)**

Normals are zero vectors. Verify the normal computation in `extrudeSketch`. For side
faces, if `edgeLen` is zero (zero-length edge in the sketch), the normal division
produces `NaN`. Add a guard: `if (edgeLen < 1e-10) continue`.

**Symptom: `extractClosedLoop` returns `null` for a rectangular sketch**

The lines are not connected — endpoints don't match within `TOLERANCE`. Log the
endpoint coordinates and verify lines were committed at snapped positions. After
snapping (lesson 09), endpoints should be identical.

Remove all temporary `console.log` statements before committing.

## What Breaks Without This

**Without counter-clockwise face winding:**
Faces appear to render but are invisible from the outside — the normals point inward.
`MeshStandardMaterial` by default culls back-faces (`THREE.FrontSide`). An inward-
pointing face is a "back face" and is not rendered. Setting `side: THREE.DoubleSide`
on the material masks this bug — the solid looks correct but has inverted normals,
which produces incorrect shading. Correct winding, not `DoubleSide`, is the fix.

**Without the modulo in side face loop:**
The last edge (from last vertex to first vertex) is not rendered. The bottom of the
extrusion has a visible gap. For a rectangle, this is a missing side face.
