# Lesson 2.25: Delegates

**What you will build.** `AssetTableModel`'s own `Category` column
(2.20, editable since 2.22) has always let `QTableView`'s own default
delegate supply a plain, free-text `QLineEdit` for editing — meaning a
user could type absolutely anything into that cell, even though
`AssetEditor.category_field` (2.9) has always used a real, fixed-list
`QComboBox` for the identical real choice. A new, small file,
`asset_manager/desktop/category_delegate.py`, defines
`CategoryDelegate(QStyledItemDelegate)` — a real, specialized editor
provider, giving the `Category` column that same real `QComboBox`
instead, for real, in-table editing. This is this lesson's own one,
real, deliberately small landing — per the blueprint's own explicit
hedge ("mostly throwaway," "we know where to go when we need one"),
this project does not gain a general delegate framework, only this one,
concrete, well-motivated example.

**What you need to know first.** Lesson 2.22 — `AssetTableModel
.setData`, `flags`, `Qt.ItemDataRole.EditRole`; a delegate is what
actually calls these, from the view's own side, once a cell is
double-clicked. Lesson 2.9 — `AssetEditor.category_field`, the real,
existing `QComboBox` this lesson's own delegate deliberately mirrors,
rather than inventing a new item list. Lesson 2.24 — `self.proxy_model`,
`AssetFilterProxyModel`; this lesson's own delegate is attached to
`self.assets_table`, meaning every index it ever receives is a
*proxy* index, the identical real fact 2.24 already established for
`on_current_row_changed`.

## Objects and methods used

**`QStyledItemDelegate`**

- *What it is:* a real class from PySide6's `QtWidgets` module — the
  real object a view (`QTableView`, 2.19) asks, per column, both how to
  *paint* a cell and, if that cell is editable (2.22), what real editor
  widget to open for it.
- *Implementation:* `QStyledItemDelegate(parent: QObject | None =
  None)`; a real subclass overrides `createEditor`, `setEditorData`,
  `setModelData`, and `updateEditorGeometry` (all below) to replace the
  view's own default, generic editing behavior for one specific column.
- *Its use:* `CategoryDelegate(QStyledItemDelegate)`, this lesson's own
  real, central subclass.
- *Type:* a class, from `PySide6.QtWidgets` — a `QObject` (2.3).
- *Responsibility:* decide, for one column, what real widget opens when
  a cell there is edited, what value that widget starts with, and what
  value gets written back — nothing about validating that value, which
  is still entirely `AssetTableModel.setData`'s own job (2.22),
  unchanged.
- *Depends on:* a real view to attach to, via `setItemDelegateForColumn`
  (below).
- *Connects to:* `QTableView` calls this delegate's own four real
  methods automatically, at the right real moments during editing;
  `setModelData` calls `model.setData` (2.22) directly.
- *Shape:* this lesson's own one, small, real customization layered on
  top of `QTableView`'s own default editing behavior — not a general
  framework, per the blueprint's own explicit hedge.

**`QStyledItemDelegate.createEditor`**

- *What it is:* a real method every `QStyledItemDelegate` subclass may
  override — builds and returns the real widget a user actually types
  or clicks into while editing one cell.
- *Implementation:* `createEditor(self, parent: QWidget, option:
  QStyleOptionViewItem, index: QModelIndex) -> QWidget`.
- *Its use:* `CategoryDelegate.createEditor` builds a real `QComboBox`
  (2.7), populated with the identical five real category strings
  `AssetEditor.category_field` (2.9) already uses.
- *Type:* an instance method, overridden on `CategoryDelegate`.
- *Responsibility:* construct exactly one real, correctly-parented
  editor widget — nothing about what value it starts showing; that's
  `setEditorData`'s own separate job, called immediately afterward.
- *Depends on:* `parent`, the real widget the new editor should be
  parented to (2.3's own ownership material, reapplied).
- *Connects to:* called by the view the instant a user starts editing a
  cell in this delegate's own column; its own return value is handed
  directly to `setEditorData`.
- *Shape:* the real, first of the delegate's own four real
  responsibilities — building the editor, before anything about its
  content or position.

**`QStyledItemDelegate.setEditorData`**

- *What it is:* a real method every `QStyledItemDelegate` subclass may
  override — populates a freshly-built editor with the model's own
  current, real value.
- *Implementation:* `setEditorData(self, editor: QWidget, index:
  QModelIndex) -> None`.
- *Its use:* `CategoryDelegate.setEditorData` reads `index.data(Qt
  .ItemDataRole.EditRole)` (2.21, 2.22) — the identical real role
  `AssetTableModel.data` already answers correctly — and calls
  `editor.setCurrentText(...)` (2.7) on the real `QComboBox` `create
  Editor` just built.
- *Type:* an instance method, overridden on `CategoryDelegate`.
- *Responsibility:* make the editor genuinely reflect this specific
  cell's own current, real value — nothing about building the editor
  itself, already done by `createEditor`.
- *Depends on:* a real editor, already built; a real, valid `index`.
- *Connects to:* called by the view immediately after `createEditor`
  returns; reads through `index`, which, once this lesson's own real
  delegate is attached to `self.assets_table` (2.24), is a real *proxy*
  index — `index.data(...)` already correctly forwards to the real
  source model, the identical real fact Lesson 2.24 already proved for
  `setData` generally.
- *Shape:* the real, second of the delegate's own four responsibilities
  — populating the editor with real, correct starting content.

**`QStyledItemDelegate.setModelData`**

- *What it is:* a real method every `QStyledItemDelegate` subclass may
  override — writes the editor's own final, real value back into the
  model once editing finishes.
- *Implementation:* `setModelData(self, editor: QWidget, model:
  QAbstractItemModel, index: QModelIndex) -> None`.
- *Its use:* `CategoryDelegate.setModelData` calls `model.setData(index,
  editor.currentText(), Qt.ItemDataRole.EditRole)` — the identical real
  `setData` contract `AssetTableModel` (2.22) and, transparently,
  `AssetFilterProxyModel` (2.24) both already implement correctly.
- *Type:* an instance method, overridden on `CategoryDelegate`.
- *Responsibility:* read the real, final value out of the editor, and
  hand it to the model via `setData` — nothing about whether that
  value is actually valid; `AssetTableModel.setData`'s own real
  validation (2.22, via `dataclasses.replace`) still decides that,
  completely unaware a delegate was ever involved.
- *Depends on:* a real, already-edited editor; the real `model` the
  view is currently showing — `self.proxy_model` (2.24), not `self
  .assets_model` directly, once this lesson's own delegate is attached.
- *Connects to:* called by the view once editing ends (Enter pressed,
  or focus lost); calls `model.setData` directly.
- *Shape:* the real, third of the delegate's own four responsibilities
  — the one that actually writes anything back at all.

**`QStyledItemDelegate.updateEditorGeometry`**

- *What it is:* a real method every `QStyledItemDelegate` subclass may
  override — positions and sizes the real editor widget within the
  cell being edited.
- *Implementation:* `updateEditorGeometry(self, editor: QWidget,
  option: QStyleOptionViewItem, index: QModelIndex) -> None` —
  `option.rect`, a real, already-computed rectangle naming exactly
  where this cell is drawn, handed to `editor.setGeometry(...)`.
- *Its use:* `CategoryDelegate.updateEditorGeometry` calls `editor
  .setGeometry(option.rect)` directly — the simplest real, correct
  implementation, making the editor fill the exact same space the cell
  itself occupies.
- *Type:* an instance method, overridden on `CategoryDelegate`.
- *Responsibility:* size and position the editor correctly — nothing
  about its content, already handled by `setEditorData`.
- *Depends on:* a real, already-built editor; `option`, a real
  `QStyleOptionViewItem` (below) the view itself provides.
- *Connects to:* called by the view whenever the cell's own real
  on-screen geometry is known or changes.
- *Shape:* the real, fourth and final delegate responsibility — purely
  visual positioning, with no effect on this lesson's own real,
  headless verification at all (this project's own real proof calls
  the other three methods directly; a real, on-screen render is the
  only thing this one visibly affects).

**`QStyleOptionViewItem`**

- *What it is:* a real class from PySide6's `QtWidgets` module — a
  plain, real data-carrying object describing how one specific cell is
  currently being drawn (its real rectangle, state, and similar).
- *Implementation:* `QStyleOptionViewItem()` — constructible with no
  arguments; carries a real `rect` attribute, among others, used by
  `updateEditorGeometry` above.
- *Its use:* `option = QStyleOptionViewItem()`, in this lesson's own
  verification, stands in for the real, fully-populated one `QTableView`
  itself would normally construct and pass automatically.
- *Type:* a class, from `PySide6.QtWidgets`.
- *Responsibility:* carry real, read-only information about a cell's
  own current visual state to whichever delegate method needs it —
  nothing about deciding that state itself; that's the view's own job.
- *Depends on:* nothing to construct; real fields are normally filled
  in by the view before being passed to a delegate.
- *Connects to:* passed to `createEditor` and `updateEditorGeometry`;
  this lesson's own delegate methods read `option.rect` from it.
- *Shape:* a real, minimal stand-in this lesson's own verification
  constructs directly, since no real view ever actually opens an editor
  in a headless, offscreen run.

**`QTableView.setItemDelegateForColumn`** *(and* `itemDelegateForColumn`*)*

- *What it is:* a real method pair every `QTableView` carries — assigns
  a specific delegate to one specific column, and reads back whichever
  one is currently assigned.
- *Implementation:* `setItemDelegateForColumn(self, column: int,
  delegate: QAbstractItemDelegate) -> None`; `itemDelegateForColumn
  (self, column: int) -> QAbstractItemDelegate`.
- *Its use:* `self.assets_table.setItemDelegateForColumn(2, self
  .category_delegate)`, this lesson's own real, central wiring — column
  `2` is `Category` (2.20's own `COLUMN_HEADERS`).
- *Type:* an instance method pair, on `QTableView` (technically
  inherited from `QAbstractItemView`).
- *Responsibility:* remember, per column, which delegate should handle
  it — nothing about columns with no delegate explicitly assigned,
  which simply keep using the view's own generic default.
- *Depends on:* a real, already-constructed delegate.
- *Connects to:* every other column (`Name`, `Serial Number`) keeps
  using `QTableView`'s own default delegate, untouched; only `Category`
  is affected.
- *Shape:* the real, single attachment point between a delegate and the
  one column it customizes.

### Isolated Concept

```python
from PySide6.QtCore import QAbstractTableModel, QModelIndex, Qt
from PySide6.QtWidgets import (
    QApplication,
    QComboBox,
    QStyledItemDelegate,
    QStyleOptionViewItem,
    QTableView,
)

app = QApplication([])


class CategoryModel(QAbstractTableModel):
    def __init__(self, rows, parent=None):
        super().__init__(parent)
        self._rows = rows

    def rowCount(self, parent=QModelIndex()):
        return len(self._rows)

    def columnCount(self, parent=QModelIndex()):
        return 1

    def data(self, index, role=Qt.ItemDataRole.DisplayRole):
        if role in (Qt.ItemDataRole.DisplayRole, Qt.ItemDataRole.EditRole):
            return self._rows[index.row()]
        return None

    def flags(self, index):
        return super().flags(index) | Qt.ItemFlag.ItemIsEditable

    def setData(self, index, value, role=Qt.ItemDataRole.EditRole):
        if role != Qt.ItemDataRole.EditRole:
            return False
        self._rows[index.row()] = value
        self.dataChanged.emit(index, index, [role])
        return True


class CategoryDelegate(QStyledItemDelegate):
    CATEGORIES = ["Laptop", "Monitor", "Keyboard", "Mouse", "Other"]

    def createEditor(self, parent, option, index):
        editor = QComboBox(parent)
        editor.addItems(self.CATEGORIES)
        return editor

    def setEditorData(self, editor, index):
        current_value = index.data(Qt.ItemDataRole.EditRole)
        editor.setCurrentText(current_value)

    def setModelData(self, editor, model, index):
        model.setData(index, editor.currentText(), Qt.ItemDataRole.EditRole)

    def updateEditorGeometry(self, editor, option, index):
        editor.setGeometry(option.rect)


model = CategoryModel(["Monitor"])
table = QTableView()
table.setModel(model)

delegate = CategoryDelegate()
table.setItemDelegateForColumn(0, delegate)

print(table.itemDelegateForColumn(0) is delegate)

index = model.index(0, 0)
option = QStyleOptionViewItem()

editor = delegate.createEditor(table, option, index)
print(type(editor))
print(editor.count())

delegate.setEditorData(editor, index)
print(editor.currentText())

editor.setCurrentText("Keyboard")
delegate.setModelData(editor, model, index)
print(model.data(index))
```

change at all; a delegate only decides *which widget* mediates an

`editor.currentText()` reads `"Monitor"`, the model's own real,
current value. `editor.setCurrentText("Keyboard")` simulates a real

### CS Lens

This is the **Strategy pattern** — extracting one specific, swappable
behavior (here, "how to edit this cell") into its own separate object,
so different columns, or different future views, can each plug in a
different real strategy without the view itself needing to know which
one is in play. This is a hard concept, worth more than one real-world
connection.

```
Also recognized in: a payment-processing system swapping between
different real payment providers behind one shared interface, a route-
planning application choosing between "fastest," "shortest," or
"avoid tolls" strategies without changing the map-drawing code at all,
a text editor's own pluggable spell-checker, swappable per language
without changing the editor itself, a sorting library accepting a
custom comparison function to change ordering behavior without
rewriting the sort itself
```

### SE Lens

The alternative not chosen is `AssetTableModel.data`/`setData` (2.22)
themselves somehow encoding, per column, what widget should be used to
edit it — mixing view-layer concerns (which widget) into the model
layer, which Lesson 2.20's own real design has deliberately kept free
of any view awareness at all. The real benefit of a delegate instead:
the model stays exactly as simple as it already is, and the *view*
decides, per column, how editing actually looks — a real, clean
separation matching the identical Model/View split (2.19, 2.20) this
project has already built around. The real cost: understanding "why
does this cell show a dropdown instead of a text box" now requires
knowing a delegate exists at all, one more real place logic can live,
alongside the model and the view themselves.
