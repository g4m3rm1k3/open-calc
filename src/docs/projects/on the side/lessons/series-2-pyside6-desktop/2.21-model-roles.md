# Lesson 2.21: Model Roles

**What you will build.** `AssetTableModel.data` (2.20) currently
answers exactly one real question — "what should this cell display?" —
and returns `None` for anything else. This lesson teaches `data`'s own
real second argument, `role`, properly: the same cell can, and often
should, answer *differently* depending on what's actually being asked.
`AssetTableModel`'s own `Name` column now answers `Qt.ItemDataRole
.DisplayRole` with `asset.display_name` (1.10) — the same "(Retired)"-
suffixed, human-friendly string this project has shown since Series 1
— while `Qt.ItemDataRole.EditRole` for that identical cell answers with
`asset.name`, the plain, undecorated field a future editor (2.22) will
need, not the decorated one. The `Serial Number` column additionally
answers `Qt.ItemDataRole.TextAlignmentRole`, right-aligning its own
real, visible text — the first time this project's own table has ever
looked different, column to column, on purpose.

**What you need to know first.** Lesson 2.20 — `AssetTableModel`,
`data`'s own real `role` parameter, already checked but only ever
against one value (`DisplayRole`); extended here, not rebuilt. Lesson
1.10 — `Asset.display_name`, the real, computed `@property` this lesson
reuses directly for the first time from the desktop layer. Lesson 1.2 —
`Asset.mark_retired`, used in this lesson's own verification to prove
`display_name` and `name` genuinely diverge once an asset is retired.

## Objects and methods used

**`Qt.ItemDataRole`**

- *What it is:* a real enum, from PySide6's `QtCore` module — names
  every distinct *kind* of question a Qt model can be asked about one
  cell; reapplied here from Lesson 2.19/2.20's own `DisplayRole`-only
  usage, now handling more of its own real members.
- *Implementation:* `Qt.ItemDataRole.DisplayRole` — the plain text to
  show; `Qt.ItemDataRole.EditRole` — the raw value an editor should
  work with, not necessarily identical to `DisplayRole`'s own string;
  `Qt.ItemDataRole.TextAlignmentRole` — how a cell's own text should be
  aligned; `Qt.ItemDataRole.ToolTipRole` — text for a hover tooltip,
  used only in this lesson's own isolated proof, to show an unhandled
  role still safely returns `None`. Many other real members exist
  (`Qt.ItemDataRole.FontRole`, `Qt.ItemDataRole.BackgroundRole`, and
  others), none used by this lesson.
- *Its use:* `AssetTableModel.data`'s own new `if role == ...` chain,
  this lesson's own real, central change — checking three specific
  members by name, in sequence, rather than the single `!=` check
  Lesson 2.20 originally wrote.
- *Type:* an enum, from `PySide6.QtCore`.
- *Responsibility:* give every possible "what do you want to know about
  this cell" question its own real, distinct name — nothing about what
  any specific model actually returns for any of them; that's each
  model's own `data` implementation.
- *Depends on:* nothing; a fixed, real set of named values Qt itself
  defines.
- *Connects to:* `QTableView` (2.19) asks for `DisplayRole` to draw
  plain text, and, once a cell becomes editable (2.22), `EditRole` to
  populate whatever editor widget it opens; asks for `TextAlignmentRole`
  every time it draws a cell, to decide how to position that cell's own
  text.
- *Shape:* the real, closed vocabulary every `data` implementation in
  this project will ever be asked about, one member at a time.

**`Qt.AlignmentFlag`**

- *What it is:* a real, combinable ("flag") enum, from PySide6's
  `QtCore` module — names real text-alignment options, any number of
  which can be combined together into a single real value.
- *Implementation:* `Qt.AlignmentFlag.AlignLeft`, `AlignRight`,
  `AlignVCenter`, and several others; combined with Python's own
  bitwise `|` operator — `Qt.AlignmentFlag.AlignRight | Qt
  .AlignmentFlag.AlignVCenter` produces one real, combined value (`130`
  on this project's own real, current platform, confirmed directly)
  that means "both, together"; checking whether a specific flag is
  present in a combined value uses the identical operator's own
  counterpart, `&` — `combined & Qt.AlignmentFlag.AlignRight` is
  non-zero exactly when `AlignRight` was one of the flags originally
  combined in.
- *Its use:* `Qt.AlignmentFlag.AlignRight | Qt.AlignmentFlag
  .AlignVCenter`, returned for `TextAlignmentRole` on the `Serial
  Number` column — right-aligned horizontally, and centered vertically,
  the real, standard combination for a single-line table cell.
- *Type:* an enum, from `PySide6.QtCore` — specifically a *flag* enum,
  meaning combining members with `|` is a real, supported, meaningful
  operation, unlike `Qt.ItemDataRole` (above), whose own members are
  never combined this way.
- *Responsibility:* represent exactly one real alignment choice, or a
  real combination of compatible ones (a horizontal choice plus a
  vertical one) — nothing about drawing anything; `QTableView` itself
  reads this value and positions the cell's own text accordingly.
- *Depends on:* nothing; a fixed, real set of named values Qt itself
  defines.
- *Connects to:* returned from `data(index, Qt.ItemDataRole
  .TextAlignmentRole)`; read directly by `QTableView` every time it
  draws that specific cell.
- *Shape:* this lesson's own second real, new vocabulary — a
  *combinable* enum, a genuinely different real shape from the ordinary,
  one-at-a-time enums (`Qt.ItemDataRole`, `QDialog.DialogCode`, 2.16)
  this project has used so far.

**`Asset.display_name`**

- *What it is:* a real, computed `@property` on `Asset` — reapplied
  from Lesson 1.10, used here for the first time from anywhere inside
  `asset_manager/desktop/`.
- *Implementation:* `display_name(self) -> str` — returns `f"{self
  .name} (Retired)"` if `self.is_retired` is `True`, otherwise plain
  `self.name`, computed fresh every single access, never stored.
- *Its use:* `asset.display_name`, `AssetTableModel.data`'s own new
  `DisplayRole` answer for column `0` — replacing the previous, plain
  `asset.name` (2.20).
- *Type:* an instance property — a method accessed with no parentheses,
  computed on demand (1.10's own real material).
- *Responsibility:* everything Lesson 1.10 already established —
  report a real, human-friendly name, decorated only when genuinely
  retired — unchanged by this lesson's own new caller.
- *Depends on:* `self.name` and `self.is_retired`, both already real,
  existing `Asset` fields (1.7, 1.2).
- *Connects to:* read by `AssetTableModel.data`'s own `DisplayRole`
  branch; deliberately *not* read by the same method's own `EditRole`
  branch, which reads `asset.name` directly instead — the real, concrete
  reason this lesson's own two roles genuinely need to differ at all.
- *Shape:* the real, working example proving `DisplayRole`/`EditRole`
  aren't an abstract distinction — `Asset` already has exactly the kind
  of decorated-versus-raw difference those two roles exist to separate.

```python
from dataclasses import dataclass

from PySide6.QtCore import QAbstractTableModel, QModelIndex, Qt
from PySide6.QtWidgets import QApplication

app = QApplication([])


@dataclass
class Reading:
    celsius: float


class TemperatureModel(QAbstractTableModel):
    def __init__(self, readings, parent=None):
        super().__init__(parent)
        self._readings = readings

    def rowCount(self, parent=QModelIndex()):
        return len(self._readings)

    def columnCount(self, parent=QModelIndex()):
        return 1

    def data(self, index, role=Qt.ItemDataRole.DisplayRole):
        reading = self._readings[index.row()]
        if role == Qt.ItemDataRole.DisplayRole:
            return f"{reading.celsius:.1f} C"
        if role == Qt.ItemDataRole.EditRole:
            return reading.celsius
        return None


readings = [Reading(21.456)]
model = TemperatureModel(readings)

index = model.index(0, 0)
print(model.data(index, Qt.ItemDataRole.DisplayRole))
print(model.data(index))
print(model.data(index, Qt.ItemDataRole.EditRole))
print(model.data(index, Qt.ItemDataRole.ToolTipRole))
```

```python
from PySide6.QtCore import QAbstractTableModel, QModelIndex, Qt
from PySide6.QtWidgets import QApplication

app = QApplication([])


class TwoColumnModel(QAbstractTableModel):
    def rowCount(self, parent=QModelIndex()):
        return 1

    def columnCount(self, parent=QModelIndex()):
        return 2

    def data(self, index, role=Qt.ItemDataRole.DisplayRole):

            return "SN-001" if index.column() == 1 else "ThinkPad X1"
        if role == Qt.ItemDataRole.TextAlignmentRole:

print(bool(alignment & Qt.AlignmentFlag.AlignVCenter))
```

connection.

```

```
