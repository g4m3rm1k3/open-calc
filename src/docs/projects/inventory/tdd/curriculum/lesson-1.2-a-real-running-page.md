# Lesson 1.2: A Page That Renders

## What you will build

The first piece of the frontend — a running Vite dev server, serving the
original application's own HTML shell, compiling and rendering a
minimal React component through it. Nothing about routing, auth, or
business data yet — this is the frontend's version of Lesson 1.1: the
smallest thing a browser can actually load and show something from.

## What you need to know first

Nothing project-specific — general JavaScript/TypeScript (functions,
`import`/`export`) is assumed; everything else is taught from scratch or
cited from `concepts/`.

## Terms introduced

- **Manifest file** — `package.json`, the file naming a project and
  everything it depends on; the first file any JS/TS tool reads.
- **Module bundler / dev server** — Vite: in development, a local server
  that compiles files on demand as the browser requests them; for
  production, a tool that bundles everything into optimized output.
- **Build-tool plugin** — a package (`@vitejs/plugin-react`) that adds a
  capability to Vite it doesn't have on its own — here, understanding
  and compiling JSX.
- **Mount point** — the one HTML element (`<div id="root">`) a
  JavaScript framework takes over and renders into.
- **Non-null assertion** — TypeScript's `!` operator, asserting a value
  the compiler thinks might be `null` is guaranteed not to be, at this
  specific point in the code.
- **`StrictMode`** — a React component that opts its subtree into extra,
  development-only checks, including deliberately calling some functions
  twice to surface hidden impurity.

## Concept Unit: A Page, Mounted

### The Problem

An `.html` file and a React component are, on their own, inert: a
static file with an empty `<div>`, and a plain function nobody's called
yet. Something has to connect them — load the file, run the script,
find the element, and hand React control of it.

### Concepts reused, 100% match — not re-taught here

- `concepts/react-dom-createroot-mounting.md` — the mount point
  (`createRoot(...).render(...)`), including its own worked example of
  exactly this HTML/`main.tsx` shape.
- `concepts/dom-get-element-by-id.md` — the DOM lookup this project's
  own `main.tsx` uses (`getElementById`, not the concept's sibling
  `querySelector` — same underlying idea, different method, matching
  the original exactly).
- `concepts/typescript-non-null-assertion.md` — the `!` after
  `document.getElementById('root')`.
- `concepts/javascript-es-modules-import-export.md` — every
  `import`/`export` line in `main.tsx`/`App.tsx`.
- `concepts/jsx-syntax.md` — the `<StrictMode>`/`<App />` JSX in
  `main.tsx`, and `App.tsx`'s own returned JSX.

### New concept, no match: `React.StrictMode`

Full treatment in `concepts/react-strict-mode.md` — not repeated here.
That file's own isolation lab proves, with a captured double-
`console.log`, that `StrictMode` deliberately runs a component's render
function twice in development, and confirms (by removing `StrictMode`
and rerunning) that without it, the identical component renders exactly
once.

### Discard the throwaway example

`concepts/react-strict-mode.md`'s own lab is discarded, per its own
file — the literal `Counter`/`renderCount` never appear in this project.

### Project Change

- **Reference Source** — the original application's `index.html` (repo
  root, in full); `src/main.tsx` (repo root, in full, minus the
  `import './index.css'` line); `src/App.tsx`, lines 450
  (`function App() {`), 515 (`return (`), 714 (`export default App;`)

- **Two deliberate deferrals, named, not silent:**

  - `main.tsx`'s `import './index.css';` line — same reason; no

  not extended**, starting the moment routing/auth/bootstrap get their
  own lessons.
- **Files affected** — Created: `index.html`, `src/main.tsx`,
  `src/App.tsx`, under your frontend folder.
- **Change type** — Add.
- **Location** — Brand-new files.
- **Dependencies** — This unit's own `package.json`/`vite.config.ts`
  from the prior Concept Unit, installed via `npm install`.

### Type this

Create `index.html`:

```html
<!DOCTYPE html>
<html lang="en" class="dark">

    <script type="module" src="/src/main.tsx"></script>
  </body>
</html>
```

Create `src/main.tsx`:

```tsx
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';

import App from './App';

const rootElement = document.getElementById('root')!;

const root = createRoot(rootElement);

root.render(
    <StrictMode>
        <App />
    </StrictMode>
);
```

Create `src/App.tsx`:

```tsx
function App() {
    return (
        <div>Rebuild in progress</div>
    );
}

export default App;
```

### Mechanical Walkthrough

- `<div id="root"></div>` — the empty element `main.tsx` mounts into;
  direct application of `react-dom-createroot-mounting.md`'s own mount-
  point concept.
- `<script type="module" src="/src/main.tsx"></script>` — direct
  application of `javascript-es-modules-import-export.md`'s module
  system, at the HTML level: this is what makes `main.tsx`'s own
  `import`/`export` lines meaningful at all.
- `<title>`/`<meta name="description">` — the original's own content,
  ported verbatim; no invented copy.
- `import { StrictMode } from 'react';` / `import { createRoot } from
  'react-dom/client';` / `import App from './App';` — direct
  application of `javascript-es-modules-import-export.md`: two named
  imports from installed packages, one default import from a local,
  relative file.
- `document.getElementById('root')!` — direct application of
  `dom-get-element-by-id.md` (the lookup) and `typescript-non-null-
  assertion.md` (the `!`) together: a genuine claim that this exact
  element exists, true by construction, since this same lesson's own
  `index.html` defines it.
- `createRoot(rootElement)` / `root.render(...)` — direct application of
  `react-dom-createroot-mounting.md`'s own mount call.
- `<StrictMode><App /></StrictMode>` — direct application of this
  lesson's own new `react-strict-mode.md` concept: every render of
  `App` during development now genuinely happens twice, discarding the
  first, matching that file's own captured proof.
- `function App() { return (<div>Rebuild in progress</div>); }` — direct
  application of `jsx-syntax.md`; the one named, temporary line inside
  it is `<div>Rebuild in progress</div>` — see Project Change's own
  stated exception, above.

### Execution Trace

The page runs, so trace what a browser actually does with it, start to
finish:

1. `npm run dev` starts Vite, listening on http://localhost:5173.
2. A browser requests `http://localhost:5173/`. Vite serves
   `index.html` as written above.
3. The browser parses the HTML, finds `<div id="root"></div>` (empty,
   nothing inside it yet), and reaches
   `<script type="module" src="/src/main.tsx"></script>`.
4. The browser requests `/src/main.tsx` as an ES module. Vite compiles
   the TypeScript/JSX on the fly and returns JavaScript.
5. `main.tsx` runs: `document.getElementById('root')!` finds the real
   `<div>` from step 2, `createRoot(rootElement)` wraps it, and
   `root.render(<StrictMode><App /></StrictMode>)` is called.
6. React calls `App()`. In development, under `StrictMode`, it calls it
   a second time and discards the first result
   (`react-strict-mode.md`'s own already-proven behavior). The kept
   result is the JSX `<div>Rebuild in progress</div>`.
7. React inserts that into the real DOM, inside `#root`. The browser now
   shows the text "Rebuild in progress" on the page.

## Connect the pieces

One page load, traced start to finish: a browser requests `index.html`,
gets the static shell this lesson wrote, and loads `/src/main.tsx` as an
ES module (`javascript-es-modules-import-export.md`'s own mechanism, now
at the browser level via Vite). `main.tsx` finds the `<div id="root">`
(`dom-get-element-by-id.md`), calls `createRoot` on it
(`react-dom-createroot-mounting.md`), and renders
`<StrictMode><App /></StrictMode>` — React's own reconciler calls the
`App` function (twice, in development — `react-strict-mode.md`), gets
back JSX (`<div>Rebuild in progress</div>`), and inserts it into the DOM
inside `#root` — proven end to end by the execution trace above.

## What breaks without this

Captured this session by temporarily removing `<div id="root"></div>`
from `index.html` (leaving `main.tsx` unchanged):

```
Uncaught TypeError: Cannot read properties of null (reading '_reactRootContainer')
```

This is the first real error message in this curriculum — read
`concepts/reading-a-stack-trace.md` now if you haven't already; every
later "What breaks without this" section assumes you can read one. The
last part of this specific message, `reading '_reactRootContainer'`,
names what React's own internal code was trying to do when it failed:
`main.tsx` calls `document.getElementById('root')!` — the `!` asserts
the element exists (`typescript-non-null-assertion.md`'s own stated
risk) — and, with no element to find, `getElementById` returns genuine
`null`; `createRoot(null)` then fails at runtime exactly the way that
concept file predicts an incorrect assertion will. Restored:

```html
    <div id="root"></div>
```

The identical page, reloaded, renders correctly again with no error.
