# 047: CSS Pill & Capsule Design Masterclass

## Overview

The **Pill** (also known geometrically as a **stadium shape**, **capsule**, or **discorectangle**) is one of the most pervasive, timeless, and aesthetically pleasing geometric primitives in modern digital interface design. From Apple iOS segmented pickers and Google Material 3 chips to Tailwind badge components and GitHub repository tags, the pill shape provides distinct visual affordance, tactile friendliness, and clean containment for compact pieces of information.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          THE PILL / CAPSULE SHAPE                           │
│                                                                             │
│               ( ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ )           │
│              (  ╭─────────────── Straight Top ───────────────╮  )          │
│             (   │                                            │   )         │
│            ( Semicircle                                  Semicircle)       │
│            (    │                                            │    )        │
│             (   │                                            │   )         │
│              (  ╰────────────── Straight Bottom ─────────────╯  )          │
│               ( ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ )           │
│                                                                             │
│      Radius (r) = Height (h) / 2        Length (L) >= Height (h)            │
└─────────────────────────────────────────────────────────────────────────────┘
```

While seemingly trivial at first glance—"just round the corners"—implementing production-grade pills and capsules in CSS involves nuanced layout mechanics, browser corner-curve reduction algorithms, optical centering challenges, accessibility pitfalls, and advanced styling tricks (such as gradient borders and animated segmented indicators).

This comprehensive masterclass dissects the mathematical mechanics, design tokens, responsive dynamics, and production-ready component architectures required to master pill and capsule UI styling in modern CSS.

## 1. Mental Model: Geometry & The "50% Border-Radius" Trap

To understand why pill styling works the way it does in CSS, we must analyze the mathematics of the CSS Box Model and the W3C CSS Backgrounds and Borders Specification.

### The Stadium Geometry vs. The Ellipse

A **stadium shape** consists of a rectangle capped on two opposing parallel sides by perfect semicircles whose radii equal exactly half the distance between those sides ($r = \frac{h}{2}$ for a horizontal capsule).

```
========================= 1. THE ELLIPSE (OVAL) =========================
Generated by: border-radius: 50% on a non-square rectangle (e.g., 240px x 60px)
Corner radii resolve to rx = 120px (50% of w) and ry = 30px (50% of h):

                      ╭─────────────────────────╮
                   ╭──                           ──╮
                ╭──                                 ──╮
               │                   OVAL                │
                ╰──                                 ──╯
                   ╰──                           ──╯
                      ╰─────────────────────────╯
             [Curvature is continuous and elongated — NOT a pill!]


========================= 2. THE PILL (STADIUM) =========================
Generated by: border-radius: 9999px (or border-radius: 1000px / 100vh / 100vmax)
Corner radii resolve to rx = 30px, ry = 30px (capped at h / 2):

               ╭───────────────────────────────────────╮
              │                                         │
             │                PILL / CAPSULE             │
              │                                         │
               ╰───────────────────────────────────────╯
             [Flat top & bottom; perfect semicircle ends on left & right]
```

### Why `border-radius: 50%` Fails on Rectangles

One of the most frequent junior CSS mistakes is applying `border-radius: 50%` to turn a button or badge into a pill.

- In CSS, percentage values for `border-radius` are resolved **relative to the corresponding dimension of the border box**:
  - Horizontal radius percentage = `% of width`
  - Vertical radius percentage = `% of height`
- When an element is a square (`width: 60px; height: 60px`), `50%` produces $r_x = 30\text{px}$ and $r_y = 30\text{px}$, generating a **perfect circle**.
- When an element is rectangular (`width: 200px; height: 50px`), `50%` produces $r_x = 100\text{px}$ and $r_y = 25\text{px}$. The result is an **egg / oval / ellipse**, which distorts visual balance and clips content awkwardly at the corners.

### The W3C Overlapping Radii Algorithm & The Large-Value Technique

To generate a true capsule whose corners remain circular arcs with radius $r = \frac{\text{height}}{2}$, regardless of dynamic width changes, CSS developers use the **Large Value Technique**:

```css
.pill {
  border-radius: 9999px; /* or 100vmax, 1000px, 999em */
}
```

#### How the Browser Evaluates `border-radius: 9999px`:
According to the [W3C CSS Backgrounds and Borders Module Level 3 (§5.5 Corner Overlapping)](https://www.w3.org/TR/css-backgrounds-3/#corner-overlap):

1. The browser computes the requested corner radii for all four corners:
   $$r_{top-left} = 9999\text{px}, \quad r_{top-right} = 9999\text{px}, \quad r_{bottom-right} = 9999\text{px}, \quad r_{bottom-left} = 9999\text{px}$$
2. The browser checks if the sum of adjacent radii exceeds the length of the edge:
   $$\text{Top Edge Sum} = 9999\text{px} + 9999\text{px} = 19998\text{px} > \text{Width}$$
   $$\text{Left Edge Sum} = 9999\text{px} + 9999\text{px} = 19998\text{px} > \text{Height}$$
3. The browser calculates a reduction scaling factor $f$:
   $$f = \min\left(\frac{\text{Width}}{r_{tl} + r_{tr}}, \, \frac{\text{Height}}{r_{tl} + r_{bl}}, \, \frac{\text{Width}}{r_{bl} + r_{br}}, \, \frac{\text{Height}}{r_{tr} + r_{br}}\right)$$
4. Since $\text{Height} < \text{Width}$ for a horizontal pill, the height constraint dominates:
   $$f = \frac{\text{Height}}{9999\text{px} + 9999\text{px}} = \frac{\text{Height}}{19998\text{px}}$$
5. The browser multiplies all radii by $f$:
   $$r_{\text{resolved}} = 9999\text{px} \times \left(\frac{\text{Height}}{19998\text{px}}\right) = \frac{\text{Height}}{2}$$
6. **Result**: Both horizontal and vertical corner radii resolve to exactly $\frac{\text{Height}}{2}$, creating an optimal semicircular cap on both sides with flat horizontal lines connecting them.

## 2. Core Comparison Matrix

| Property / Technique | Visual Result on Rectangular Box | Behavior on Content Expansion | Best Used For |
| :--- | :--- | :--- | :--- |
| **`border-radius: 50%`** | Distorted Ellipse / Oval | Elliptical curvature stretches | Avatar portraits, circular icon buttons (square boxes only) |
| **`border-radius: 9999px`** | True Semicircular Pill / Stadium | Automatically recalculates to $\frac{\text{height}}{2}$ | Dynamic-width badges, tags, pill CTAs, filter chips |
| **`border-radius: 100vmax`** | True Semicircular Pill | Scales relative to maximum viewport dimension | Breakpoint-free layout tokens, design system utilities |
| **`border-radius: calc(var(--h) / 2)`** | Exact Semicircular Pill | Requires explicit `--h` height variable | Fixed-height buttons, toggle switches, tab bars |
| **`border-radius: 8px` (Fixed)** | Rounded Rectangle | Fixed radius regardless of dimensions | Cards, dialog modals, standard form inputs |

## 3. Optical Centering & Spacing Mechanics

A common flaw in pill components is unbalanced horizontal spacing. Because the left and right ends of a pill curve aggressively inward, content (such as text or icons) placed near the edges appears visually cramped if standard rectangular padding is used.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       OPTICAL INSET ON PILL CURVES                          │
│                                                                             │
│   WRONG: Equal Padding (padding: 8px 12px)                                  │
│   ╭──────────────────────────────────────────────────╮                      │
│  │*Text too close to curve*                          *Too close* │         │
│   ╰──────────────────────────────────────────────────╯                      │
│                                                                             │
│   RIGHT: Optical Pill Ratio (Horizontal padding ≈ 1.5x - 2.0x Vertical)    │
│   ╭────────────────────────────────────────────────────────────╮            │
│  │   [Icon]  Optimal Breathing Room Inside Capsule  [Badge]   │            │
│   ╰────────────────────────────────────────────────────────────╯            │
│      |<---- Semicircular Cap Inset ---->|                                   │
└─────────────────────────────────────────────────────────────────────────────┘
```

### The Golden Formula for Pill Padding
For single-line pills (chips, badges, buttons):
$$\text{Padding-Inline (Horizontal)} \approx 1.5 \times \text{Padding-Block (Vertical)} + \frac{\text{Border-Radius}}{4}$$

In practice with modern CSS design tokens:
```css
:root {
  --pill-pad-block-sm: 0.25rem;  /* 4px */
  --pill-pad-inline-sm: 0.625rem; /* 10px (~2.5x block) */

  --pill-pad-block-md: 0.5rem;   /* 8px */
  --pill-pad-inline-md: 1.125rem; /* 18px (~2.25x block) */

  --pill-pad-block-lg: 0.75rem;  /* 12px */
  --pill-pad-inline-lg: 1.75rem;  /* 28px (~2.3x block) */
}
```

## 5. Advanced CSS Techniques & Edge Cases

### 1. The Multiline Wrap Dilemma

What happens if the text inside a pill expands or wraps onto multiple lines?

```
========================= 1. WITHOUT CONTROLS =========================
Pill radius (9999px) on multiline block turns into an awkward rounded block:

           ╭────────────────────────────────────────╮
          │ This is a very long pill message that   │
         │ has wrapped across multiple lines and   │
          │ looks awkward with massive ends         │
           ╰────────────────────────────────────────╯

========================= 2. CONTROLLED HYBRID =========================
Using CSS Container Queries to switch from pill to rounded rectangle:

           ╭────────────────────────────────────────╮
           │ This is a long message that gracefully │
           │ converted to a standard rounded card.  │
           ╰────────────────────────────────────────╯
```

#### Solution: Container Query Adaptive Radii
```css
.pill-container {
  container-type: inline-size;
}

.adaptive-pill {
  /* Default single-line pill */
  border-radius: 9999px;
  white-space: nowrap;
}

/* If container narrows or pill is forced to wrap */
@container (max-width: 320px) {
  .adaptive-pill {
    border-radius: 12px; /* Smoothly degrades to a modern rounded rectangle */
    white-space: normal;
  }
}
```

### 2. Inner Glow & Box-Shadow Curvature Clamping

When applying `box-shadow` or `inset` shadows to a pill, the shadow automatically follows the curved geometry. However, multiple nested borders can cause pixel gap artifacts if not calculated properly:

```css
.perfect-shadow-pill {
  border-radius: 9999px;
  
  /* Multi-layered physical depth */
  box-shadow:
    /* Layer 1: Sharp crisp top highlight */
    inset 0 1px 0 0 rgba(255, 255, 255, 0.25),
    /* Layer 2: Subtle inner bottom shadow */
    inset 0 -1px 0 0 rgba(0, 0, 0, 0.3),
    /* Layer 3: Soft ambient ground drop */
    0 4px 12px rgba(0, 0, 0, 0.25),
    /* Layer 4: Deep ground contact */
    0 1px 3px rgba(0, 0, 0, 0.4);
}
```

## 6. Accessibility (a11y) & UX Engineering

Creating accessible pill components requires adhering to W3C WAI-ARIA and WCAG 2.1/2.2 guidelines:

### 1. Focus Ring Integrity (`:focus-visible`)
Do not remove focus outlines. Because native `outline` in older browsers was rectangular, modern browsers support `outline` conforming to `border-radius`. Ensure sufficient offset:

```css
.pill-element:focus-visible {
  outline: 2px solid #3b82f6;
  outline-offset: 3px; /* Prevents focus ring from clipping into the curve */
}
```

### 2. Minimum Touch Target Sizing (WCAG 2.5.5 / 2.5.8)
Compact pill badges and chips often have a visual height of $24\text{px}$ to $28\text{px}$. On touch devices, the minimum accessible target size is **$44\text{px} \times 44\text{px}$** (iOS HIG) or **$48\text{px} \times 48\text{px}$** (Android / WCAG AAA).

Use an invisible pseudo-element expansion:
```css
.pill-chip {
  position: relative;
  /* Visual height: 28px */
  padding: 0.35rem 0.85rem;
}

/* Touch Target Expander without altering visual layout */
.pill-chip::before {
  content: "";
  position: absolute;
  top: 50%;
  left: 50%;
  transform: translate(-50%, -50%);
  min-width: 48px;
  min-height: 48px;
  width: 100%;
  height: 100%;
}
```

### 3. Color Contrast Ratios (WCAG 1.4.3)
Tinted / pastel pills frequently suffer from low contrast text.
- **Normal Text (< 18pt)**: Requires at least **4.5:1** contrast against badge background AND badge background must contrast against the page.
- Always verify contrast between the pill's text color and its background container.

## 7. DOs and DON'Ts

| Aspect | DO | DON'T |
| :--- | :--- | :--- |
| **Corner Radius** | `border-radius: 9999px` (or `100vmax`) for automatic height-responsive semicircles. | `border-radius: 50%` on non-square rectangles (creates ugly ovals). |
| **Horizontal Inset** | Give pills 1.5x–2.5x more horizontal padding than vertical padding to offset the inward curve. | Use equal vertical and horizontal padding (causes text to collide with arcs). |
| **Gradient Borders** | Use `background: linear-gradient(...) padding-box, linear-gradient(...) border-box`. | `border-image: linear-gradient(...)` (breaks `border-radius`). |
| **Multiline Text** | Set `white-space: nowrap` for badges/chips, or switch to `border-radius: 12px` via container queries if wrapping is allowed. | Allow multiline text inside a `9999px` radius box without layout boundaries. |
| **Touch Sizing** | Expand the hit area to 44px+ using `::before` pseudo-elements on interactive chips. | Make interactive 20px tall buttons without hit target padding. |
| **Focus Outlines** | Use `:focus-visible` with `outline-offset: 2px` to respect the capsule shape. | Disable `outline: none` without a high-contrast custom replacement. |
