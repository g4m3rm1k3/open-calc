## Concept Unit: Domain and Persistence, Kept Apart

### The Problem

This project's own earlier persistence work built `CalculationEntity`,
a real, permanent, deliberately separate type from the real, existing
`Calculation` — and its own SE Lens named the real, honest cost of that
choice directly: "two types
now exist that both describe 'a calculation' in some sense... something
will eventually need to convert between them." That gap has to close
before either type can actually be useful together. The real
complication: `Calculation.operator` is the real, type-safe `Operator`
enum, but `CalculationEntity.operator` is a plain `String`, since SQLite
has no native concept of a Kotlin enum at all.

### Introduce the Concept in Isolation

```kotlin
enum class LabColor {
    RED, GREEN, BLUE
}

data class LabShape(val color: LabColor, val sides: Int)
data class LabShapeRow(val id: Long, val color: String, val sides: Int)

fun LabShape.toRow(): LabShapeRow = LabShapeRow(id = 0, color = color.name, sides = sides)
fun LabShapeRow.toDomain(): LabShape = LabShape(color = LabColor.valueOf(color), sides = sides)

fun main() {
    val original = LabShape(LabColor.GREEN, 4)
    val row = original.toRow()
    println(row)

    val roundTripped = row.toDomain()
    println(roundTripped)
    println(original == roundTripped)
}
```

Real, executed output:

```

LabShape(color=GREEN, sides=4)
true
```

This proves the real mechanism directly: `.name` really does turn
`LabColor.GREEN` into the literal string `"GREEN"`, real and printed;
`LabColor.valueOf("GREEN")` really does turn that same string back into
the exact original constant; and the real, final `true` proves the
round trip is lossless — a `LabShape` converted to a row and back is
structurally identical to the one it started as, confirmed by `data
class`'s own real, generated `equals`. This two-function pattern is
called a **mapper** — code whose only real job is translating between
two different representations of the same real-world concept, never
adding or deciding anything else.

### Introduce the Concept in Isolation

```kotlin
data class LabItem(val name: String)
data class LabItemRow(val id: Long, val name: String)

fun LabItem.toRow(): LabItemRow = LabItemRow(id = 0, name = name)
fun LabItemRow.toDomain(): LabItem = LabItem(name = name)

interface LabItemDao {
    fun insert(row: LabItemRow)
    fun getAll(): List<LabItemRow>
}

class LabInMemoryDao : LabItemDao {
    private val rows = mutableListOf<LabItemRow>()
    private var nextId = 1L

    override fun insert(row: LabItemRow) {
        rows.add(row.copy(id = nextId))
        nextId++
    }

    override fun getAll(): List<LabItemRow> = rows
}

class LabItemRepository(private val dao: LabItemDao) {
    fun save(item: LabItem) {
        dao.insert(item.toRow())
    }

    fun getAll(): List<LabItem> {
        return dao.getAll().map { it.toDomain() }
    }
}

fun main() {
    val repository = LabItemRepository(LabInMemoryDao())
    repository.save(LabItem("apple"))
    repository.save(LabItem("banana"))
    println(repository.getAll())
}
```

            AppDatabase::class.java
        ).allowMainThreadQueries().build()
        repository = CalculationRepository(database.calculationDao())
    }

    @After
    fun closeDatabase() {
        database.close()
    }

    @Test
    fun savedCalculationCanBeReadBackAsARealDomainCalculation() {
        // Arrange
        val calculation = Calculation(operator = Operator.PLUS, operandA = 7, operandB = 3, result = 10)

        // Act
        repository.save(calculation)
        val all = repository.getAll()

        // Assert
        assertEquals(listOf(calculation), all)
    }
}
