# OpenCalc Theme Engine Guide

The OpenCalc UI has two primary environments: the **Course layout** and the **Studio (IDE) layout**. Because these serve different visual needs, the theming engine is split into specific layers to maximize flexibility and ensure the UI looks incredible in every state.

## 1. Studio Themes (`src/utils/studioThemes.js`)

This file defines the available themes for the IDE environment (e.g., Dracula, Nord, Vue). 

- **UI Classes:** Each theme defines explicit Tailwind classes for its backgrounds and text (e.g., `bg0: 'bg-[#282a36]'`).
- **Markdown (`mdLight`/`mdDark`):** Defines the exact hex colors used for rendering markdown content within that theme.
- **Hex Extraction Rule:** For the dynamic theme engine to work, `bg0`, `bg1`, `bg2`, `border`, `txt1`, and `txt2` **must** include an explicit `#hex` code in their string (e.g., `bg-[#0b1322]`). Do not use raw Tailwind named colors (like `bg-slate-900/50`) here, because the engine needs to extract the raw hex value to generate the palette.

## 2. Dynamic Variable Generation (`src/utils/themeEngine.js`)

When a Studio Theme is selected, the application does *not* just apply the raw Tailwind classes globally. Instead, `themeEngine.js` dynamically hijacks Tailwind's default palette.

1. **Extraction:** It uses a regex to extract the hex values from `uiDark`'s `bg0`, `bg1`, `bg2`, `border`, etc.
2. **Palette Generation:** It mathematically generates full 50-950 scales based on these hexes.
   - `slate`: The neutral UI scale. Interpolated smoothly from the extracted backgrounds, borders, and text colors.
   - `brand`: The primary accent scale, generated from `themeDef.accentHex`.
   - `sky`: The secondary accent scale, generated by hue-rotating the primary accent by 130 degrees.
3. **Injection:** These scales are injected into the DOM as `--tw-custom-slate-*`, `--tw-custom-brand-*`, etc.

**Why?** This means that inside the UI code, developers can just write `bg-slate-900`. Tailwind is configured (in `tailwind.config.js`) so that `slate-900` looks up `--tw-custom-slate-900`. Thus, `bg-slate-900` automatically perfectly matches the active theme (whether that's Dracula's purple-tinted grey, or Nord's blue-tinted grey).

## 3. The Hook (`src/hooks/useThemeColors.js`)

React components use this hook to easily access semantic colors.

- **DOM Rendering:** It provides colors referencing the CSS variables (e.g., `rgb(var(--tw-custom-brand-500))`) so they update live.
- **Canvas Rendering:** Because HTML5 Canvas (`ctx.fillStyle`) cannot resolve `var(...)` CSS properties, this hook explicitly computes pure `#hex` values for canvas operations. *Always use the `canvas*` properties when drawing to Canvas.*

## 4. Course Themes (`src/styles/courseColors.js`)

Unlike the IDE, the Course/Chapter UI uses fixed semantic themes (like Indigo, Emerald, Rose) that are chosen per-course to give each curriculum a unique vibe.

- These are defined via `courseColors.js` as objects containing pre-baked Tailwind gradient classes (e.g., `from-indigo-600 via-purple-500 to-indigo-800`), glow box-shadow definitions, and text colors.
- These themes power the premium glassmorphism aesthetics across the app (like `AppCard` and `StartMenu`). Components combine these gradients with overlay blend modes and blurred abstract orbs to create a sleek, frosted 3D look.
- They do *not* go through the `themeEngine.js` dynamic extraction, as they are completely independent of the user's selected IDE preference.

## Golden Rules for Adding Components

1. **Use `slate` for neutrals:** Always use `bg-slate-*`, `text-slate-*`, and `border-slate-*` for standard UI. Do not use `gray`, `zinc`, or `neutral`, as they will bypass the dynamic theme engine.
2. **Use `brand` for primary actions:** Buttons and highlights should use `brand` (e.g., `bg-brand-500`), which automatically adapts to the theme.
3. **Use semantic colors for status:** Use the fixed semantic colors (Teal, Amber, Red) for things that must retain their meaning regardless of the theme.
4. **Never hardcode hexes in CSS classes:** Using `bg-[#123456]` directly in a JSX component breaks theme switching. Rely on the `slate` scale.
