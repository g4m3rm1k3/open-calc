# Templates: Generic Programming and Why C++ is So Fast

Consider a simple problem: write a function that returns the maximum of two values. In Python, you write it once — `def max(a, b): return a if a > b else b` — and it works for integers, floats, strings, and anything else that supports `>`. Python doesn't care about types at definition time.

In early C++, you had to write the function separately for every type you needed:

```cpp
int    maxInt   (int a,    int b)    { return a > b ? a : b; }
double maxDouble(double a, double b) { return a > b ? a : b; }
float  maxFloat (float a,  float b)  { return a > b ? a : b; }
```

Identical logic, repeated three times. Change the logic — change it three times. Add a type — add a new overload. This is the maintenance nightmare that C++ **templates** were designed to eliminate.

## Function Templates: Write Once, Compile for Every Type

```cpp
#include <iostream>
#include <string>

// Template function: T is a type parameter
template<typename T>
T maximum(T a, T b) {
    return a > b ? a : b;
}

int main() {
    std::cout << maximum(3, 7) << std::endl;           // T = int
    std::cout << maximum(3.14, 2.72) << std::endl;     // T = double
    std::cout << maximum('a', 'z') << std::endl;       // T = char
    std::cout << maximum(std::string("apple"), std::string("banana")) << std::endl;  // T = string
    // All of these are generated as separate functions at compile time
}
```

This is **compile-time polymorphism**. When you call `maximum(3, 7)`, the compiler looks at the argument types (`int`), substitutes `T = int`, and generates an actual `int maximum(int a, int b)` function. When you call `maximum(3.14, 2.72)`, it generates `double maximum(double a, double b)`. These are completely separate functions in the compiled binary — no shared code, no runtime type checking, no virtual dispatch.

The implication: **there is zero overhead**. The compiler generates specialized, fully optimized code for each type. You get the maintainability of writing it once and the performance of writing it for every type separately.

## Class Templates: Generic Data Structures

The standard library containers — `std::vector<T>`, `std::map<K, V>`, `std::unique_ptr<T>` — are all class templates. Let's build a simple one:

```cpp
#include <iostream>
#include <stdexcept>

template<typename T, int MaxSize>
class FixedStack {
private:
    T data[MaxSize];
    int top = 0;

public:
    void push(const T& value) {
        if (top >= MaxSize) throw std::overflow_error("Stack full");
        data[top++] = value;
    }

    T pop() {
        if (top == 0) throw std::underflow_error("Stack empty");
        return data[--top];
    }

    T peek() const {
        if (top == 0) throw std::underflow_error("Stack empty");
        return data[top - 1];
    }

    bool empty() const { return top == 0; }
    int size() const { return top; }
};

int main() {
    FixedStack<int, 10> intStack;
    intStack.push(1);
    intStack.push(2);
    intStack.push(3);
    std::cout << "Top: " << intStack.peek() << std::endl;
    std::cout << "Pop: " << intStack.pop() << std::endl;
    std::cout << "Size: " << intStack.size() << std::endl;

    // Same class, completely different type — no extra code written
    FixedStack<std::string, 5> stringStack;
    stringStack.push("hello");
    stringStack.push("world");
    std::cout << stringStack.pop() << " " << stringStack.pop() << std::endl;
}
```

`FixedStack<int, 10>` and `FixedStack<std::string, 5>` are completely independent classes generated by the compiler from the same template. The `MaxSize` parameter is a **non-type template parameter** — an integer baked into the type, known at compile time. This means the array is stack-allocated (no heap allocation), and the size check `if (top >= MaxSize)` might even be optimized out in some cases.

## Template Specialization: Different Behavior for Specific Types

Sometimes a generic implementation is correct for most types but wrong for a specific one. **Template specialization** lets you provide an alternative:

```cpp
#include <iostream>
#include <cmath>
#include <cstring>

// Generic template
template<typename T>
bool areEqual(T a, T b) {
    return a == b;
}

// Specialization for double — floating point needs epsilon comparison
template<>
bool areEqual<double>(double a, double b) {
    return std::abs(a - b) < 1e-10;
}

// Specialization for const char* — C-strings need strcmp
template<>
bool areEqual<const char*>(const char* a, const char* b) {
    return std::strcmp(a, b) == 0;
}

int main() {
    std::cout << std::boolalpha;
    std::cout << areEqual(5, 5) << std::endl;            // Generic: true
    std::cout << areEqual(0.1 + 0.2, 0.3) << std::endl; // Specialized: true (epsilon)
    std::cout << areEqual("hello", "hello") << std::endl; // Specialized: true (strcmp)
}
```

## `if constexpr` and Compile-Time Branching in Templates

Templates often need to behave differently based on type properties. `if constexpr` (C++17) lets you do this at compile time:

```cpp
#include <iostream>
#include <type_traits>
#include <string>

template<typename T>
void describe(T value) {
    if constexpr (std::is_integral_v<T>) {
        std::cout << "Integer " << value
                  << " is " << (value % 2 == 0 ? "even" : "odd")
                  << ", occupies " << sizeof(T) << " bytes" << std::endl;
    } else if constexpr (std::is_floating_point_v<T>) {
        std::cout << "Float " << value
                  << " rounded = " << static_cast<long long>(value + 0.5) << std::endl;
    } else if constexpr (std::is_same_v<T, std::string>) {
        std::cout << "String \"" << value << "\" has "
                  << value.length() << " characters" << std::endl;
    } else {
        std::cout << "Unknown type" << std::endl;
    }
}

int main() {
    describe(42);
    describe(42LL);
    describe(3.14159);
    describe(std::string("hello"));
}
```

Unlike a normal `if`, branches in `if constexpr` that aren't taken are discarded before the code is compiled — they don't even need to be syntactically valid for the given type. This is what makes metaprogramming in C++ tractable.

## C++20 Concepts: Constrained Templates

Templates have one major weakness: when you call a template with a type that doesn't support the required operations, the error messages are notoriously bad — sometimes pages of template instantiation errors pointing to internals of the standard library, not your code.

**Concepts** (C++20) let you specify requirements on template parameters explicitly:

```cpp
#include <iostream>
#include <concepts>
#include <vector>
#include <string>

// Concept: T must support < operator and printing
template<typename T>
concept Printable = requires(T t, std::ostream& os) {
    { os << t } -> std::same_as<std::ostream&>;
};

template<typename T>
concept Comparable = requires(T a, T b) {
    { a < b } -> std::same_as<bool>;
};

// Constrained template: T must satisfy both concepts
template<Comparable T> requires Printable<T>
T maximum(T a, T b) {
    T result = a > b ? a : b;
    std::cout << "Max of [" << a << ", " << b << "] = " << result << std::endl;
    return result;
}

int main() {
    maximum(3, 7);
    maximum(3.14, 2.72);
    maximum(std::string("apple"), std::string("banana"));

    // If you tried: maximum(std::vector<int>{}, std::vector<int>{})
    // You'd get a clear error: "vector doesn't satisfy Comparable"
    // Instead of pages of template instantiation noise
}
```

## Monomorphization vs Type Erasure

Understanding why C++ templates are different from Java generics illuminates why C++ is so fast.

Java uses **type erasure** for generics: `ArrayList<Integer>` and `ArrayList<String>` are the *same class at runtime*. The type parameter is erased and replaced with `Object`. This means boxing (wrapping primitives in heap objects) and unboxing (extracting them) at every operation. A `List<Integer>` stores boxed integers — each one a separate heap allocation.

C++ uses **monomorphization**: `std::vector<int>` and `std::vector<std::string>` are *different classes*. The compiler generates separate, fully optimized code for each. `std::vector<int>` stores actual `int` values — no boxing, no heap allocation per element, cache-friendly contiguous memory.

```cpp
#include <iostream>
#include <vector>
#include <chrono>

int main() {
    const int N = 10000000;

    auto start = std::chrono::high_resolution_clock::now();

    std::vector<int> v;
    v.reserve(N);
    for (int i = 0; i < N; i++) v.push_back(i);

    long long sum = 0;
    for (int n : v) sum += n;

    auto end = std::chrono::high_resolution_clock::now();
    auto ms = std::chrono::duration_cast<std::chrono::milliseconds>(end - start).count();

    std::cout << "Sum: " << sum << std::endl;
    std::cout << "Time: " << ms << " ms" << std::endl;
    // 10 million ints, contiguous in memory, no boxing
    // Java equivalent with ArrayList<Integer> would be ~10x slower
}
```

Templates are the mechanism that makes `std::vector<int>` as fast as a hand-written dynamic array of ints. They're the mechanism that makes `std::sort` as fast as a hand-written sort for each type. They're the mechanism that makes C++ the "zero-overhead abstraction" language — where you pay only for what you use, and what you use costs as little as if you'd written it by hand.

This is the promise that Bjarne Stroustrup made in 1983, and templates are how C++ has kept it.
