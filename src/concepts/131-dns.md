## Definition

DNS (Domain Name System) translates human-readable domain names
(example.com) into the numeric IP addresses computers actually use to
route network traffic to each other — the internet's equivalent of a phone
book, looking up a name to find an address.

## Problem

Computers route traffic using numeric IP addresses, but humans can't
reasonably memorize or type strings of numbers for every website they
visit. DNS provides a lookup system translating a memorable name into the
actual address needed to establish a connection.

## Execution

Browser wants to connect to "example.com"
↓
Browser asks a DNS resolver: "what's the IP address for example.com?"
↓
Resolver looks it up — possibly asking several other DNS servers in turn,
following a hierarchy — and returns an answer: 93.184.216.34
↓
Browser now connects directly to 93.184.216.34 — the actual network
connection uses the IP address, never the domain name itself

## Computer Science

DNS is a distributed, hierarchical lookup system — no single server holds
every domain's answer. Resolving a name involves querying a hierarchy
(root servers, then servers for the specific top-level domain, then the
specific domain's own nameserver) that collectively knows the full
mapping, with caching at every level to avoid repeating the full hierarchy
lookup for every single request.

Tags: Hierarchical lookup, Distributed system, Caching, Name resolution

## Software Engineering

DNS results are cached, both by browsers/OS and by intermediate DNS
servers, for a specified time-to-live (TTL) — this is why changing a
domain's DNS record doesn't take effect everywhere instantly; cached
copies elsewhere continue returning the old answer until their TTL
expires.

Tags: Time-to-live, DNS caching, Propagation delay

## Common Mistakes

- Expecting a DNS change to take effect everywhere immediately — cached records at various points across the internet continue serving the old answer until their individual TTLs expire, sometimes taking hours.
- Confusing DNS resolution failures with the actual destination server being down — if DNS itself can't resolve a name to an address, the connection never even gets a chance to reach the real server, a different failure mode than the server being unreachable once addressed correctly.

## Exercises

- Look up your own machine's DNS resolver configuration, and explain in your own words what a "DNS cache" on your computer is actually storing.
- Explain why a TTL of 5 minutes versus 24 hours matters differently for a domain's owner who's about to change its IP address.

## javascript

```javascript
// Simulating a simplified DNS lookup with caching, since a real DNS query
// requires an actual network. This demonstrates the lookup-then-cache shape.
class FakeDNS {
  #records = { 'example.com': '93.184.216.34' }
  #cache = new Map()
  #lookups = 0

  resolve(domain) {
    if (this.#cache.has(domain)) return this.#cache.get(domain)   // cache hit -- no lookup needed
    this.#lookups++
    const ip = this.#records[domain]
    this.#cache.set(domain, ip)
    return ip
  }
}

const dns = new FakeDNS()
console.log(dns.resolve('example.com'))   // '93.184.216.34' — first call, a real lookup happens
console.log(dns.resolve('example.com'))   // '93.184.216.34' — second call, served from cache
```
Walkthrough: the first `resolve` call performs an actual lookup and caches
the result; the second call for the same domain returns the cached answer
directly, without repeating the lookup — exactly why a DNS change doesn't
propagate everywhere instantly, since existing caches keep answering with
the old value until they expire.

## python

```python
class FakeDNS:
    def __init__(self):
        self._records = {'example.com': '93.184.216.34'}
        self._cache = {}
        self.lookups = 0

    def resolve(self, domain):
        if domain in self._cache:
            return self._cache[domain]   # cache hit -- no lookup needed
        self.lookups += 1
        ip = self._records[domain]
        self._cache[domain] = ip
        return ip


dns = FakeDNS()
print(dns.resolve('example.com'))   # '93.184.216.34' -- first call, a real lookup happens
print(dns.resolve('example.com'))   # '93.184.216.34' -- second call, served from cache
print(dns.lookups)                   # 1 -- only ONE real lookup happened, despite two resolve() calls
```
Walkthrough: identical lookup-then-cache mechanics as the JavaScript
version — `dns.lookups` staying at `1` after two `resolve()` calls proves
the second call was served entirely from the cache.
