## Definition

A set stores a collection of values with no duplicates and no guaranteed
order — its core operation is checking whether a value is already present.

## Problem

Keeping a list of "things seen so far" and checking membership with an array
means scanning the whole array every time to check for duplicates — a set does
that check directly, and automatically refuses to store the same value twice.

## Computer Science

Like a map, a set is typically backed by a hash table — checking membership
(`has`/`in`) is O(1) on average, the same speed regardless of how many items the
set already holds. A set is really "a map where you only care about the keys, not
any associated value."

Tags: Hash table, Deduplication, Membership testing

## Software Engineering

Reach for a set whenever the requirement is fundamentally "no duplicates" or "does
this exist yet" — deduplicating a list of IDs, tracking which users have already
been emailed today. Using an array with a manual `.includes()` check for the same
purpose works but gets slower as the collection grows, unlike a set's near-constant
membership check.

Tags: Deduplication, Data structure selection, Membership checks

## Common Mistakes

- Expecting a set to preserve insertion order the way an array does — some languages guarantee it (JavaScript's `Set` does), others don't guarantee it at all.
- Adding an object or a mutable value to a set and later mutating it — the set's internal deduplication was based on the value's state *at insertion time*, so this can produce confusing behavior.

## Exercises

- In the JavaScript example, add `'apple'` to the set a second time and confirm the size doesn't change.
- In Python, convert a list with duplicate values to a set and observe how many items remain.

## javascript

```javascript
const seen = new Set()
seen.add('apple')
seen.add('banana')
seen.add('apple')          // duplicate — ignored
console.log(seen.size)     // 2
console.log(seen.has('apple'))   // true
```
Walkthrough: adding `'apple'` a second time has no effect — a `Set` silently
refuses duplicates rather than erroring. `.size` reports the count of *distinct*
values, `2`, not the number of `.add()` calls made, `3`.

## python

```python
seen = {'apple', 'banana'}
seen.add('apple')          # duplicate — ignored
print(len(seen))           # 2
print('apple' in seen)     # True
```
Walkthrough: Python's set literal uses curly braces, like a dict, but with no
colons — just bare values, since a set has no associated value per key, only
membership. Behavior is otherwise identical to JavaScript's `Set`.

## java

```java
import java.util.Set;
import java.util.HashSet;

Set<String> seen = new HashSet<>();
seen.add("apple");
seen.add("banana");
seen.add("apple");          // duplicate — ignored
System.out.println(seen.size());          // 2
System.out.println(seen.contains("apple")); // true
```
Walkthrough: `HashSet` is Java's standard hash-table-backed set — same behavior as
the other two languages. Unlike JavaScript's `Set`, `HashSet` makes **no guarantee**
about iteration order at all — a real difference worth knowing if code ever
depends on the order items come back when iterating a Java set.
